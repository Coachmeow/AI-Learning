# เอกสารออกแบบ: เว็บเรียน AI สองภาษา (ไทย / English)

> เอกสารนี้เป็นพิมพ์เขียวของโปรเจกต์ ใช้อ้างอิงทุกรอบการทำงาน
> ถ้าเริ่ม session ใหม่ ให้อ่านไฟล์นี้ก่อน แล้วดูหัวข้อ "แผนการทำงานเป็นรอบ" ว่าทำถึงไหนแล้ว

## 1. เป้าหมาย

1. นำเนื้อหาทั้งหมดของ [rohitg00/ai-engineering-from-scratch](https://github.com/rohitg00/ai-engineering-from-scratch) (MIT) มาทำเป็นเว็บของเราเอง
2. เลือกได้ 2 ภาษา คือ ไทย และ English สลับได้ทุกหน้า
3. ใช้เรียนเองได้ และเป็นสื่อการสอนให้คนอื่นเข้ามาเรียนด้วยกันได้
4. มี interactive คือแผนภาพที่ลากปรับค่าได้ และปุ่มรันโค้ดในหน้าเว็บ
5. มีแบบทดสอบหลังเรียน 2 แบบ คือ **แบบเลือกตอบ** และ **แบบลงมือเขียนโค้ดจริง**
6. เลือกระดับความยากของแบบทดสอบได้ 3 ระดับ คือ ง่าย / กลาง / ยาก
7. หน้าตาสวยงาม อ่านภาษาไทยสบายตา มีโหมดสว่างและโหมดมืด
8. ดาวน์โหลดไปรันบนเครื่องได้ **โดยไม่ต้องต่อเน็ต** (ไม่ใช้ CDN ใดๆ ตอนเปิดดู)

## 3. แนวทางเทคนิคที่เลือก

**Astro + Starlight** สร้างเป็นเว็บ static (ได้ไฟล์ HTML/CSS/JS ล้วน)

| ความต้องการ | วิธีทำ |
|---|---|
| สองภาษา | ใช้ระบบ i18n ของ Starlight ทำ `/th/...` และ `/en/...` บทไหนยังไม่แปล จะแสดงต้นฉบับอังกฤษพร้อมป้าย "ยังไม่ได้แปล" |
| ค้นหา | Pagefind สร้างดัชนีค้นหาตอน build ใช้งานได้ offline |
| interactive | คอมโพเนนต์ JS แยกเป็นเกาะเล็กๆ (islands) และนำโค้ดแผนภาพของต้นฉบับมาใช้ (MIT) |
| รัน Python ในเบราว์เซอร์ | Pyodide (Python ที่คอมไพล์เป็น WebAssembly) ทำงานใน Web Worker เก็บไฟล์ไว้ในเว็บเอง โหลดเฉพาะตอนกดรันครั้งแรก |
| ช่องเขียนโค้ด | CodeMirror 6 (เบากว่า Monaco มาก) |
| สูตรคณิต / แผนผัง | KaTeX แปลงสูตรตอน build ส่วน Mermaid เก็บไฟล์ไว้ในเว็บเอง |
| ฟอนต์ | ใช้แพ็กเกจ @fontsource เก็บไฟล์ฟอนต์ไว้ในเว็บ ไม่เรียก Google Fonts |
| เก็บความคืบหน้า | localStorage ในเบราว์เซอร์ของผู้เรียน ส่งออกและนำเข้าเป็นไฟล์ JSON ได้ |
| เผยแพร่ | GitHub Pages (ฟรี) และไฟล์ zip ใน GitHub Releases สำหรับคนที่อยากเรียน offline |

**เวอร์ชันที่ใช้จริง (รอบนำร่อง):** Astro 7.4 + Starlight 0.43, Pyodide 314.0 (ชื่อเวอร์ชันใหม่ตาม CPython 3.14), KaTeX 0.19, Mermaid 12, CodeMirror 6 ทุกแพ็กเกจปักเวอร์ชันแบบตรงตัวใน `package.json`

**สิ่งที่ต่างจากความรู้เดิมของเวอร์ชันก่อนๆ (ใช้อ้างอิงตอนแก้โค้ด):**
- Astro 7 ใช้ตัวประมวลผล Markdown ชื่อ Sätteri เป็นค่าเริ่มต้น เราสลับไปใช้ `unified()` จาก `@astrojs/markdown-remark` เพื่อใช้ปลั๊กอิน remark ได้ (`astro.config.mjs`)
- Starlight 0.39 ขึ้นไป กลุ่มเมนูต้องเขียนเป็น `{ label, items: [{ autogenerate: { directory } }] }`
- Pyodide รุ่นนี้รันได้เฉพาะใน module worker (`new Worker(url, { type: 'module' })` แล้ว `import()` ไฟล์ `pyodide.mjs`)

**เหตุผลที่ไม่ fork เว็บต้นฉบับทั้งก้อน:** repo ต้นฉบับมีขนาดประมาณ 250 MB และเว็บผูกกับแบรนด์ของเขา (มีไฟล์ใน `site/` 242 ไฟล์)
เราจึงทำเว็บใหม่ที่เบากว่า แล้วดึงมาเฉพาะเนื้อหากับชิ้นส่วนที่ใช้ซ้ำได้ ส่วนที่ใช้ซ้ำคือแผนภาพ interactive กับโจทย์ practice

## 5. การออกแบบหน้าตา

**แนวทางภาพ:** สะอาด อ่านง่าย มีพื้นที่ว่างมาก เน้นตัวหนังสือ ใช้สีเน้นแค่สีเดียว

- **ฟอนต์:** IBM Plex Sans Thai สำหรับข้อความไทยและอังกฤษ (เข้าชุดกัน) และ JetBrains Mono สำหรับโค้ด
- **ระยะบรรทัด:** ข้อความไทยใช้ line-height ประมาณ 1.8 เพราะมีสระบนล่างและวรรณยุกต์ ความกว้างบรรทัดไม่เกินประมาณ 70 ตัวอักษร
- **สี:** สีเน้นโทนน้ำเงินคราม ใช้เขียวสำหรับ "ผ่าน" และส้มสำหรับ "ลองใหม่" มีธีมสว่างและมืด กำหนดเป็น CSS variables
- **ภาษา:** ปุ่ม `ไทย | EN` อยู่มุมขวาบน และจำค่าที่เลือกไว้ ภายหลังอาจเพิ่มปุ่ม "ดูต้นฉบับ" ทีละย่อหน้า

### หน้าหลัก
- ส่วนหัว (hero) บอกว่าเว็บนี้คืออะไร มีปุ่ม "เรียนต่อจากที่ค้างไว้"
- เส้นทางการเรียน 3 เส้นทาง: พื้นฐานโมเดล / ระบบ LLM / Agent
- การ์ด 20 phase แต่ละใบแสดงวงแหวนความคืบหน้า จำนวนบท และสัดส่วนที่แปลแล้ว

### หน้าอื่นๆ
- **แดชบอร์ด:** ความคืบหน้าราย phase คะแนนแบบทดสอบแยกตามระดับ จำนวนวันที่เรียนต่อเนื่อง ปุ่มส่งออก/นำเข้าความคืบหน้า
- **คลังโจทย์ฝึก:** โจทย์ practice ทั้งหมด กรองตามระดับ หัวข้อ และ phase ได้
- **อภิธานศัพท์:** คำอังกฤษ ↔ ไทย พร้อมคำอธิบาย คำศัพท์ในบทเรียนจะมีกล่องคำอธิบายขึ้นเมื่อชี้
- **เกี่ยวกับ / เครดิต:** ที่มาของเนื้อหา สัญญาอนุญาต และวิธีดาวน์โหลดไปใช้ offline

## 6. แบบทดสอบเลือกตอบ (แบ่งระดับ)

### ความหมายของแต่ละระดับ

| ระดับ | วัดอะไร | ตัวอย่าง |
|---|---|---|
| ง่าย | จำและเข้าใจนิยาม | "ReAct loop มี 3 ส่วน คืออะไร" |
| กลาง | ประยุกต์ใช้ อ่านโค้ดแล้วทำนายผล | "โค้ดนี้พิมพ์อะไรออกมา" หรือ "ถ้าเพิ่ม learning rate เป็น 10 เท่า จะเกิดอะไร" |
| ยาก | วิเคราะห์ หาบั๊ก เลือก trade-off | "agent วนเรียก tool เดิมซ้ำ สาเหตุที่เป็นไปได้มากที่สุดคือข้อใด" |

### รูปแบบคำถาม
เลือกคำตอบเดียว / เลือกได้หลายข้อ / ถูก-ผิด / ทำนายผลลัพธ์ของโค้ด / เรียงลำดับขั้นตอน

### เป้าหมายจำนวนข้อ
ระดับละ 5 ข้อ รวม 15 ข้อต่อบท
- นำคำถามเดิมของต้นฉบับ (5–8 ข้อ) มาจัดระดับ
- แต่งข้อที่ขาดเพิ่ม
- บทที่ไม่มี quiz เลยต้องแต่งใหม่ทั้งหมด

### การทำงานในหน้าเว็บ
- สุ่มลำดับข้อและตัวเลือกทุกครั้ง
- ตอบแล้วเห็นเฉลยพร้อมคำอธิบายทันที
- ได้ 70% ขึ้นไปถือว่าผ่านระดับนั้น
- เก็บคะแนนดีที่สุดของแต่ละระดับ
- โหมด "ผสม" สุ่มคำถามจากทุกระดับ

## 9. การใช้งานแบบ offline

1. `npm run build` จะได้โฟลเดอร์ `dist/` ซึ่งเป็นเว็บ static ทั้งหมด รวม Pyodide ฟอนต์ ดัชนีค้นหา และแผนภาพ
2. เปิดใช้บนเครื่องด้วยวิธีใดวิธีหนึ่ง:
   - `npm run preview`
   - ดับเบิลคลิก `start.bat` (Windows) หรือ `start.sh` (macOS/Linux) ซึ่งเปิดเซิร์ฟเวอร์เล็กๆ บนเครื่อง แล้วเปิดเบราว์เซอร์ให้
3. **ข้อควรรู้:** เปิดไฟล์ HTML ตรงๆ แบบ `file://` จะใช้ไม่ได้ เพราะเบราว์เซอร์ไม่ยอมให้โหลด WebAssembly และดัชนีค้นหาแบบนั้น จึงต้องมีสคริปต์ `start`
4. GitHub Actions จะสร้างไฟล์ zip ของ `dist/` แนบไว้ใน Releases คนอื่นดาวน์โหลด แตกไฟล์ แล้วดับเบิลคลิก `start` ได้เลย
5. (ภายหลัง) ทำเป็น PWA ให้เวอร์ชันออนไลน์ เลือกดาวน์โหลดเก็บไว้ใช้ offline ทีละ phase ได้

ขนาดจริงของ `dist/` หลังรอบ 1: ประมาณ 190 MB (1,088 หน้า HTML ประมาณ 77 KB ต่อหน้า, ดัชนีค้นหา 17 MB, ไฟล์ประกอบบทเรียน 32 MB, Pyodide + numpy 19 MB) บีบเป็น zip จะเล็กลงมาก

## 10. แนวทางการแปล (style guide)

ใช้แนวทางนี้ทุกรอบ เพื่อให้คำแปลทุกบทเป็นสำนวนเดียวกัน

- เขียนไทยให้เป็นธรรมชาติ ไม่แปลตามโครงประโยคอังกฤษคำต่อคำ
- **ศัพท์เทคนิค:** ครั้งแรกในบทให้เขียนไทยแล้วตามด้วยวงเล็บอังกฤษ เช่น "การไล่ระดับความชัน (gradient descent)" ครั้งต่อไปใช้แบบใดแบบหนึ่งตาม `glossary/th.json`
- คำที่คนไทยในวงการใช้ทับศัพท์จนเป็นปกติให้คงทับศัพท์ เช่น โมเดล, เอเจนต์, prompt, token, embedding, fine-tune
- **ห้ามแปล:** โค้ด ชื่อตัวแปร ชื่อฟังก์ชัน สูตรคณิต ชื่อ paper ชื่อไลบรารี ผลลัพธ์ที่โค้ดพิมพ์ออกมา
- คอมเมนต์ในโค้ดคงเป็นภาษาอังกฤษ เพราะไฟล์โค้ดใช้ร่วมกันทั้งสองภาษา
- ใส่ `source_hash` (sha256 ของ en.md ตอนแปล) ใน frontmatter เพื่อตรวจว่าคำแปลล้าสมัยหรือไม่เมื่อต้นฉบับอัปเดต
- ก่อนแปลบทไหน ให้เพิ่มคำศัพท์ใหม่ของบทนั้นลง `glossary/th.json` ก่อน

### ขั้นตอนทำเนื้อหาไทยต่อบท (ใช้ Phase 00 เป็นแบบอย่าง)
1. `node scripts/import-content.mjs --lesson <phase>/<lesson>` (ถ้ายังไม่ได้นำเข้า)
2. แปลเต็มบทไปที่ `src/content/docs/th/<phase>/<lesson>.md` คัดลอก frontmatter `upstream_*` และ `source_hash` จากฉบับอังกฤษ (**อ่าน frontmatter จากไฟล์จริง อย่าพิมพ์ hash เอง**) ห้ามแก้โค้ด สูตร ผลลัพธ์ของโปรแกรม (บล็อก `text`) และบล็อก figure แปลได้เฉพาะป้ายใน Mermaid และบล็อกที่ไม่ระบุภาษาซึ่งเป็นข้อความอธิบาย (เช่น ตารางเปรียบเทียบที่วางเป็นตัวอักษร)
3. รัน `npm run test:thai` (`scripts/check-thai.py`) ตรวจว่า frontmatter ตรง บล็อกโค้ด สูตร และ figure เหมือนต้นฉบับทุก byte (บล็อกที่ไม่ระบุภาษาที่แปลไปจะขึ้นเป็น note ให้ตรวจด้วยตา)
4. เขียน spec ของ quiz แล้วสร้างด้วย `python3 scripts/make-quiz.py <spec.json>`: คำถามเดิมของต้นฉบับใส่แค่เลขข้อกับคำแปลไทย (สคริปต์คัดลอกภาษาอังกฤษแบบไม่แก้ให้เอง, `pre` = ง่าย, `check`/`post` = กลาง ปรับได้ด้วย `"d"`) คำถามใหม่ใส่ทั้งสองภาษา ให้ครบระดับละ 5 ข้อ รันโค้ดหรือคำสั่งจริงตรวจคำตอบทุกข้อที่ตรวจได้ (ผลลัพธ์ของโค้ด, คำสั่ง shell, git, ssh -G, chmod, rsync)
5. ทำโจทย์ 3 ระดับใน `src/data/exercises/<phase>/<lesson>/` (meta.json, starter.py, solution.py, tests.py, mutants/) ใช้แต่ไลบรารีมาตรฐาน (รันใน Pyodide ได้) ระดับยากมี test ซ่อน แล้วรัน `npm run test:exercises` ทุก mutant ต้องถูกจับ**ด้วยเหตุผลที่ถูก** (อ่านข้อความที่ checker พิมพ์)
6. ถ้าบทมีแผนภาพ ดึงข้อความด้วย `node scripts/figure-text.cjs <phase>/<lesson>` แล้วเพิ่มคำแปลใน `src/data/figure-i18n.th.json` (คงโค้ดและชื่อสั้นๆ ทางเทคนิคเป็นอังกฤษ เพราะตารางนี้ใช้ทั้งเว็บ) สคริปต์เห็นแค่ข้อความตามค่าที่แสดงอยู่ตอนนั้น ข้อความที่มีตัวเลขหรือเปลี่ยนตามค่าที่เลื่อน ให้ดูทุกแบบจากโค้ดใน `public/vendor/figures/*.js` แล้วเขียนเป็น `patterns` (regex ที่ยึดหัวท้ายด้วย `^...$` และแทนค่าด้วย `$1`) ทดสอบกับตัวอย่างจริงก่อนบันทึก
7. เพิ่มคำศัพท์ใหม่ลง `glossary/th.json` แล้ว `npm run build` และ `node scripts/browser-check.cjs <phase>/<lesson>` (ต้องเปิดเว็บไว้ที่พอร์ต 4321) ตรวจว่า quiz ทุกระดับตอบถูกได้ 5/5 และเฉลยทุกระดับผ่านใน Pyodide
8. commit และ push ทีละบท GitHub Actions จะตรวจซ้ำ (ลิงก์, `check-thai.py`, `check-exercises.py`) แล้วเผยแพร่ขึ้นเว็บ

## 13. ความเสี่ยงและวิธีรับมือ

| ความเสี่ยง | วิธีรับมือ |
|---|---|
| ค้นหาภาษาไทยไม่แม่น เพราะไทยไม่มีเว้นวรรคระหว่างคำ | ทดสอบ Pagefind ในรอบ 1 ถ้าตัดคำไม่ดี ให้ตัดคำด้วย `Intl.Segmenter('th')` ก่อนสร้างดัชนี |
| ข้อความในแผนภาพเป็นอังกฤษฝังในโค้ด | รอบแรกใช้แบบอังกฤษไปก่อน แล้วค่อยแยกข้อความออกมาเป็นตารางแปล |
| Pyodide มีขนาดใหญ่ (หลายสิบ MB) | โหลดเฉพาะตอนกดรันครั้งแรก และเบราว์เซอร์เก็บแคชไว้ |
| ต้นฉบับอัปเดตบ่อย | ปัก commit ไว้ใน `upstream.lock.json` ซิงก์เมื่อพร้อม แล้วใช้ `check-translations` หาบทที่ต้องแปลใหม่ |
| คำแปลหลายรอบสำนวนไม่ตรงกัน | ใช้ style guide (ข้อ 10) และ `glossary/th.json` เป็นมาตรฐานเดียว |
| คำถามที่แต่งใหม่อาจผิด | เก็บที่มาของคำถาม (`origin`) และสุ่มตรวจทุก phase |
| ความคืบหน้าเก็บแค่ในเบราว์เซอร์ | มีปุ่มส่งออก/นำเข้า ส่วนระบบบัญชีผู้ใช้หรือใบประกาศที่ตรวจสอบได้ต้องมี backend จึงยังไม่อยู่ในขอบเขต |
