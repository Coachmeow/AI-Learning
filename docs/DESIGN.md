# เอกสารออกแบบ: เว็บเรียน AI สองภาษา (ไทย / English)

> เอกสารนี้เป็นพิมพ์เขียวของโปรเจกต์ ใช้อ้างอิงทุกรอบการทำงาน
> ถ้าเริ่ม session ใหม่ ให้อ่านไฟล์นี้ก่อน แล้วดูหัวข้อ "แผนการทำงานเป็นรอบ" ว่าทำถึงไหนแล้ว

## 1. เป้าหมาย

1. นำเนื้อหาทั้งหมดของ [rohitg00/ai-engineering-from-scratch](https://github.com/rohitg00/ai-engineering-from-scratch) (MIT) มาทำเป็นเว็บของเราเอง
2. เลือกได้ 2 ภาษา คือ ไทย และ English สลับได้ทุกหน้า
3. ใช้เรียนเองได้ และเป็นสื่อการสอนให้คนอื่นเข้ามาเรียนด้วยกันได้
4. มี interactive คือแผนภาพที่ลากปรับค่าได้ และปุ่มรันโค้ดในหน้าเว็บ
5. มีแบบทดสอบหลังเรียน 2 แบบ คือ **แบบเลือกตอบ** และ **แบบลงมือเขียนโค้ดจริง**
6. เลือกระดับความยากของแบบทดสอบได้ 3 ระดับ คือ ง่าย / กลาง / ยาก
7. หน้าตาสวยงาม อ่านภาษาไทยสบายตา มีโหมดสว่างและโหมดมืด
8. ดาวน์โหลดไปรันบนเครื่องได้ **โดยไม่ต้องต่อเน็ต** (ไม่ใช้ CDN ใดๆ ตอนเปิดดู)

## 5. การออกแบบหน้าตา

**แนวทางภาพ:** สะอาด อ่านง่าย มีพื้นที่ว่างมาก เน้นตัวหนังสือ ใช้สีเน้นแค่สีเดียว

- **ฟอนต์:** IBM Plex Sans Thai สำหรับข้อความไทยและอังกฤษ (เข้าชุดกัน) และ JetBrains Mono สำหรับโค้ด
- **ระยะบรรทัด:** ข้อความไทยใช้ line-height ประมาณ 1.8 เพราะมีสระบนล่างและวรรณยุกต์ ความกว้างบรรทัดไม่เกินประมาณ 70 ตัวอักษร
- **สี:** สีเน้นโทนน้ำเงินคราม ใช้เขียวสำหรับ "ผ่าน" และส้มสำหรับ "ลองใหม่" มีธีมสว่างและมืด กำหนดเป็น CSS variables
- **ภาษา:** ปุ่ม `ไทย | EN` อยู่มุมขวาบน และจำค่าที่เลือกไว้ ภายหลังอาจเพิ่มปุ่ม "ดูต้นฉบับ" ทีละย่อหน้า

### หน้าหลัก
- ส่วนหัว (hero) บอกว่าเว็บนี้คืออะไร มีปุ่ม "เรียนต่อจากที่ค้างไว้"
- เส้นทางการเรียน 3 เส้นทาง: พื้นฐานโมเดล / ระบบ LLM / Agent
- การ์ด 20 phase แต่ละใบแสดงวงแหวนความคืบหน้า จำนวนบท และสัดส่วนที่แปลแล้ว

## 6. แบบทดสอบเลือกตอบ (แบ่งระดับ)

### ความหมายของแต่ละระดับ

| ระดับ | วัดอะไร | ตัวอย่าง |
|---|---|---|
| ง่าย | จำและเข้าใจนิยาม | "ReAct loop มี 3 ส่วน คืออะไร" |
| กลาง | ประยุกต์ใช้ อ่านโค้ดแล้วทำนายผล | "โค้ดนี้พิมพ์อะไรออกมา" หรือ "ถ้าเพิ่ม learning rate เป็น 10 เท่า จะเกิดอะไร" |
| ยาก | วิเคราะห์ หาบั๊ก เลือก trade-off | "agent วนเรียก tool เดิมซ้ำ สาเหตุที่เป็นไปได้มากที่สุดคือข้อใด" |

### รูปแบบคำถาม
เลือกคำตอบเดียว / เลือกได้หลายข้อ / ถูก-ผิด / ทำนายผลลัพธ์ของโค้ด / เรียงลำดับขั้นตอน

### เป้าหมายจำนวนข้อ
ระดับละ 5 ข้อ รวม 15 ข้อต่อบท
- นำคำถามเดิมของต้นฉบับ (5–8 ข้อ) มาจัดระดับ
- แต่งข้อที่ขาดเพิ่ม
- บทที่ไม่มี quiz เลยต้องแต่งใหม่ทั้งหมด

### การทำงานในหน้าเว็บ
- สุ่มลำดับข้อและตัวเลือกทุกครั้ง
- ตอบแล้วเห็นเฉลยพร้อมคำอธิบายทันที
- ได้ 70% ขึ้นไปถือว่าผ่านระดับนั้น
- เก็บคะแนนดีที่สุดของแต่ละระดับ
- โหมด "ผสม" สุ่มคำถามจากทุกระดับ

## 7. แบบทดสอบลงมือทำ (hands-on)

### 7.1 โจทย์ประจำบทเรียน (ทำใหม่ทุกบท)

| ระดับ | ลักษณะโจทย์ |
|---|---|
| ง่าย | เติมโค้ด 1–3 บรรทัดตรงจุด `TODO` ในโค้ดของบทเรียน มีคำใบ้ให้มาก |
| กลาง | เขียนฟังก์ชันหลักของบทเอง จาก starter ที่มีแค่ชื่อฟังก์ชันกับคำอธิบาย |
| ยาก | ต่อยอดจากบท: จัดการกรณีขอบ ทำให้เร็วขึ้น หรือเพิ่มความสามารถใหม่ บางส่วนของ tests ซ่อนไว้ |

ไฟล์ของแต่ละโจทย์ใช้รูปแบบเดียวกับ practice ของต้นฉบับ เพื่อให้ใช้ตัวรันตัวเดียวกันได้:

```text
exercises/<phase>/<lesson>/medium/
  meta.json        ระดับ เวลาโดยประมาณ ฟังก์ชันที่ต้องเขียน
  problem.th.md    โจทย์ภาษาไทย
  problem.en.md    โจทย์ภาษาอังกฤษ
  starter.py       โค้ดเริ่มต้น
  solution.py      เฉลย (แสดงหลังทำผ่าน หรือเมื่อกดยอมแพ้)
  tests.py         ตัวตรวจ แสดงข้อความสองภาษาว่าผิดตรงไหน
  hints.json       คำใบ้ 2–4 ขั้น จากใบ้เบาๆ ไปจนถึงแนวคิดหลัก
```

### 7.2 การรันโค้ด
- ผู้เรียนเขียนโค้ดใน CodeMirror แล้วกด "ตรวจคำตอบ"
- โค้ดรันใน Pyodide ภายใน Web Worker จำกัดเวลา 10 วินาที
- ผลแสดงเป็นรายการ ✓/✗ ทีละ test พร้อมเหตุผลเป็นภาษาไทย
- ทำผ่านแล้วจึงเปิดเฉลยกับคำอธิบายเพิ่มเติม

### 7.3 บทที่รันในเบราว์เซอร์ไม่ได้ (68 บท)
บทเหล่านี้ต้องใช้ torch, transformers หรือ API key จึงมีทางเลือกดังนี้:
- ปุ่ม "ดาวน์โหลดโจทย์" แล้วรัน `python check.py` บนเครื่องตัวเอง
- หรือทำโจทย์ฉบับ numpy ที่สอนแนวคิดเดียวกันแทน

## 8. ส่วน interactive ในบทเรียน

1. **แผนภาพ interactive 553 จุด:** นำโค้ดมาจากต้นฉบับ (`site/lesson-figures.js` + `site/figures-*.js`) แล้วปรับสีให้เข้าธีมของเรา ข้อความในภาพจะทยอยแปลเป็นไทย
2. **ปุ่ม ▶ รัน ใต้โค้ด Python/JS ในบทเรียน:** ใช้ได้กับ 466 บท แก้โค้ดแล้วรันซ้ำได้ทันที
3. **กล่องอธิบายคำศัพท์:** ชี้ที่คำศัพท์แล้วเห็นคำแปลและความหมายจาก `glossary/th.json`
4. **แบบทดสอบก่อนเรียน (ไม่บังคับ):** ใช้คำถามแบบ `pre` ของต้นฉบับ ไว้ให้ผู้เรียนเช็กพื้นฐานของตัวเองก่อนเริ่ม

## 9. การใช้งานแบบ offline

1. `npm run build` จะได้โฟลเดอร์ `dist/` ซึ่งเป็นเว็บ static ทั้งหมด รวม Pyodide ฟอนต์ ดัชนีค้นหา และแผนภาพ
2. เปิดใช้บนเครื่องด้วยวิธีใดวิธีหนึ่ง:
   - `npm run preview`
   - ดับเบิลคลิก `start.bat` (Windows) หรือ `start.sh` (macOS/Linux) ซึ่งเปิดเซิร์ฟเวอร์เล็กๆ บนเครื่อง แล้วเปิดเบราว์เซอร์ให้
3. **ข้อควรรู้:** เปิดไฟล์ HTML ตรงๆ แบบ `file://` จะใช้ไม่ได้ เพราะเบราว์เซอร์ไม่ยอมให้โหลด WebAssembly และดัชนีค้นหาแบบนั้น จึงต้องมีสคริปต์ `start`
4. GitHub Actions จะสร้างไฟล์ zip ของ `dist/` แนบไว้ใน Releases คนอื่นดาวน์โหลด แตกไฟล์ แล้วดับเบิลคลิก `start` ได้เลย
5. (ภายหลัง) ทำเป็น PWA ให้เวอร์ชันออนไลน์ เลือกดาวน์โหลดเก็บไว้ใช้ offline ทีละ phase ได้

ขนาดโดยประมาณของ `dist/`: 100–200 MB เพราะมีประมาณ 1,100 หน้า บวก Pyodide และ numpy

## 10. แนวทางการแปล (style guide)

ใช้แนวทางนี้ทุกรอบ เพื่อให้คำแปลทุกบทเป็นสำนวนเดียวกัน

- เขียนไทยให้เป็นธรรมชาติ ไม่แปลตามโครงประโยคอังกฤษคำต่อคำ
- **ศัพท์เทคนิค:** ครั้งแรกในบทให้เขียนไทยแล้วตามด้วยวงเล็บอังกฤษ เช่น "การไล่ระดับความชัน (gradient descent)" ครั้งต่อไปใช้แบบใดแบบหนึ่งตาม `glossary/th.json`
- คำที่คนไทยในวงการใช้ทับศัพท์จนเป็นปกติให้คงทับศัพท์ เช่น โมเดล, เอเจนต์, prompt, token, embedding, fine-tune
- **ห้ามแปล:** โค้ด ชื่อตัวแปร ชื่อฟังก์ชัน สูตรคณิต ชื่อ paper ชื่อไลบรารี ผลลัพธ์ที่โค้ดพิมพ์ออกมา
- คอมเมนต์ในโค้ดคงเป็นภาษาอังกฤษ เพราะไฟล์โค้ดใช้ร่วมกันทั้งสองภาษา
- ใส่ `source_hash` (sha256 ของ en.md ตอนแปล) ใน frontmatter เพื่อตรวจว่าคำแปลล้าสมัยหรือไม่เมื่อต้นฉบับอัปเดต
- ก่อนแปลบทไหน ให้เพิ่มคำศัพท์ใหม่ของบทนั้นลง `glossary/th.json` ก่อน
