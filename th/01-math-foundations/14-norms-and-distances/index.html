นอร์มและระยะทาง (Norms and Distances)

แปลจากต้นฉบับ · ตรงกับต้นฉบับฉบับล่าสุดอ่านฉบับภาษาอังกฤษบทต้นฉบับบน GitHub

ฟังก์ชันระยะทางของคุณเป็นตัวกำหนดว่า “คล้ายกัน” แปลว่าอะไร เลือกผิดแล้วทุกอย่างที่ตามมาก็พัง

ประเภท: ลงมือสร้าง (Build) ภาษา: Python, TypeScript ความรู้ที่ควรมีก่อน: Phase 1 บทที่ 01 (พีชคณิตเชิงเส้นแบบเข้าใจภาพ), 02 (เวกเตอร์ เมทริกซ์ และการดำเนินการ) เวลา: ~90 นาที

สิ่งที่จะได้เรียนรู้

หัวข้อที่มีชื่อว่า “สิ่งที่จะได้เรียนรู้”
  • เขียนฟังก์ชันระยะทาง L1, L2, cosine, Mahalanobis, Jaccard และ edit distance ตั้งแต่ศูนย์
  • เลือกมาตรวัดระยะทางที่เหมาะกับงาน ML และอธิบายว่าทำไมทางเลือกอื่นจึงใช้ไม่ได้
  • เชื่อมโยงนอร์ม L1 และ L2 กับ regularization แบบ LASSO และ Ridge และบริเวณข้อจำกัดเชิงเรขาคณิตของมัน
  • แสดงให้เห็นว่าชุดข้อมูลเดียวกันให้เพื่อนบ้านที่ใกล้ที่สุดต่างกันเมื่อใช้มาตรวัดต่างกัน

ปัญหา

หัวข้อที่มีชื่อว่า “ปัญหา”

คุณมีเวกเตอร์สองตัว อาจเป็น word embedding อาจเป็นโปรไฟล์ผู้ใช้ อาจเป็นอาร์เรย์ของพิกเซล คุณต้องรู้ว่ามันใกล้กันแค่ไหน

คำตอบขึ้นกับฟังก์ชันระยะทางที่คุณเลือกทั้งหมด จุดข้อมูลสองจุดอาจเป็นเพื่อนบ้านที่ใกล้ที่สุดภายใต้มาตรวัดหนึ่ง แต่อยู่ห่างกันภายใต้อีกมาตรวัดหนึ่ง ตัวจำแนก KNN ระบบแนะนำ ฐานข้อมูลเวกเตอร์ อัลกอริทึมจัดกลุ่ม และฟังก์ชันความสูญเสียของคุณ ล้วนขึ้นกับการเลือกนี้ เลือกผิดแล้วโมเดลก็จะ optimize สิ่งที่ผิด

ไม่มีระยะทางที่ดีที่สุดสำหรับทุกงาน L2 ใช้ได้ดีกับข้อมูลเชิงพื้นที่ cosine similarity ครองงาน NLP Jaccard รับมือกับเซต edit distance รับมือกับสตริง Mahalanobis คิดถึงสหสัมพันธ์ Wasserstein เคลื่อนย้ายมวลของความน่าจะเป็น แต่ละตัวมีสมมติฐานต่างกันว่า “คล้ายกัน” แปลว่าอะไร

บทนี้สร้างฟังก์ชันระยะทางหลักทุกตัวตั้งแต่ศูนย์ แสดงว่าแต่ละตัวเหมาะกับงานไหน และสาธิตว่าข้อมูลชุดเดียวกันให้เพื่อนบ้านที่ใกล้ที่สุดต่างกันโดยสิ้นเชิงตามมาตรวัดที่ใช้

แนวคิด

หัวข้อที่มีชื่อว่า “แนวคิด”

นอร์ม: วัดขนาดของเวกเตอร์

หัวข้อที่มีชื่อว่า “นอร์ม: วัดขนาดของเวกเตอร์”

นอร์ม (norm) วัด “ขนาด” ของเวกเตอร์ ฟังก์ชันระยะทางระหว่างเวกเตอร์สองตัวทุกตัวเขียนได้เป็นนอร์มของผลต่าง: d(a,b)=∥a−b∥ การเข้าใจนอร์มจึงเท่ากับเข้าใจระยะทาง

นอร์ม L1 (ระยะทางแบบแมนฮัตตัน)

หัวข้อที่มีชื่อว่า “นอร์ม L1 (ระยะทางแบบแมนฮัตตัน)”

นอร์ม L1 รวมค่าสัมบูรณ์ของทุกองค์ประกอบ

∥x∥1​=∣x1​∣+∣x2​∣+⋯+∣xn​∣

เรียกว่าระยะทางแบบแมนฮัตตัน (Manhattan distance) เพราะมันวัดระยะที่คุณเดินบนถนนตารางในเมืองที่เดินได้แค่ตามแกน ห้ามเดินทแยง

เมื่อไรควรใช้ L1:

  • ข้อมูลเบาบาง (sparse) มิติสูง (คุณลักษณะของข้อความ การเข้ารหัสแบบ one-hot)
  • เมื่อต้องการความทนทานต่อค่าผิดปกติ (ผลต่างใหญ่ ๆ ค่าเดียวไม่ครอบงำ)
  • ปัญหาการเลือกคุณลักษณะ (L1 regularization ส่งเสริมความเบาบาง)

ความเชื่อมโยงกับ L1 regularization (Lasso): การบวก ∥w∥1​ เข้ากับฟังก์ชันความสูญเสียลงโทษผลรวมของค่าสัมบูรณ์ของน้ำหนัก ซึ่งดันน้ำหนักเล็ก ๆ ให้เป็นศูนย์พอดี เป็นการเลือกคุณลักษณะอัตโนมัติ บทลงโทษ L1 สร้างบริเวณข้อจำกัดรูปข้าวหลามตัดในปริภูมิน้ำหนัก และมุมของข้าวหลามตัดอยู่บนแกน ซึ่งเป็นจุดที่น้ำหนักบางตัวเป็นศูนย์

ความเชื่อมโยงกับฟังก์ชันความสูญเสีย: Mean Absolute Error (MAE) คือค่าเฉลี่ยของระยะ L1 ระหว่างคำทำนายกับเป้าหมาย มันลงโทษทุกความคลาดเคลื่อนแบบเชิงเส้น จึงทนต่อค่าผิดปกติได้ดีกว่า MSE

นอร์ม L2 (ระยะทางแบบยุคลิด)

หัวข้อที่มีชื่อว่า “นอร์ม L2 (ระยะทางแบบยุคลิด)”

นอร์ม L2 คือระยะทางเป็นเส้นตรง รากที่สองของผลรวมกำลังสองขององค์ประกอบ

∥x∥2​=x12​+x22​+⋯+xn2​​

นี่คือระยะทางที่คุณเรียนในวิชาเรขาคณิต ทฤษฎีบทพีทาโกรัสใน n มิติ

เมื่อไรควรใช้ L2:

  • ข้อมูลต่อเนื่องมิติต่ำถึงปานกลาง
  • เมื่อสเกลของคุณลักษณะเทียบกันได้
  • ระยะทางทางกายภาพ (ข้อมูลเชิงพื้นที่ ค่าจากเซนเซอร์)
  • ความคล้ายของภาพในระดับพิกเซล

ความเชื่อมโยงกับ L2 regularization (Ridge): การบวก ∥w∥22​ เข้ากับฟังก์ชันความสูญเสียลงโทษน้ำหนักที่ใหญ่ ต่างจาก L1 ตรงที่มันไม่ได้ดันน้ำหนักให้เป็นศูนย์ มันหดน้ำหนักทุกตัวเข้าหาศูนย์ตามสัดส่วน บทลงโทษ L2 สร้างบริเวณข้อจำกัดรูปวงกลม จึงไม่มีมุมบนแกน น้ำหนักจะเล็กลงแต่แทบไม่เป็นศูนย์พอดี

ความเชื่อมโยงกับฟังก์ชันความสูญเสีย: Mean Squared Error (MSE) คือค่าเฉลี่ยของระยะ L2 ยกกำลังสอง การยกกำลังสองลงโทษความคลาดเคลื่อนใหญ่หนักกว่าความคลาดเคลื่อนเล็ก

MAE (L1 loss):MSE (L2 loss):​∣y−y^​∣(y−y^​)2​​Linear penalty. Robust to outliers.Quadratic penalty. Sensitive to outliers.​

(MAE ลงโทษแบบเชิงเส้นและทนต่อค่าผิดปกติ MSE ลงโทษแบบกำลังสองและอ่อนไหวต่อค่าผิดปกติ)

นอร์ม Lp: ตระกูลทั่วไป

หัวข้อที่มีชื่อว่า “นอร์ม Lp: ตระกูลทั่วไป”

L1 และ L2 เป็นกรณีพิเศษของนอร์ม Lp:

∥x∥p​=(∣x1​∣p+∣x2​∣p+⋯+∣xn​∣p)1/p

ค่า p ต่างกันให้ “ลูกบอลหนึ่งหน่วย” (เซตของจุดทั้งหมดที่ห่างจากจุดกำเนิดไม่เกิน 1 รูปข้างล่างคือขอบของมัน) รูปร่างต่างกัน:

นอร์ม L-infinity (ระยะทางแบบเชบีเชฟ)

หัวข้อที่มีชื่อว่า “นอร์ม L-infinity (ระยะทางแบบเชบีเชฟ)”

เมื่อ p เข้าใกล้อนันต์ นอร์ม Lp ลู่เข้าสู่ค่าสัมบูรณ์ที่มากที่สุดขององค์ประกอบ

∥x∥∞​=max(∣x1​∣,∣x2​∣,…,∣xn​∣)

ระยะห่างระหว่างสองจุดถูกกำหนดด้วยมิติเดียวที่ต่างกันมากที่สุด มิติอื่นทั้งหมดถูกมองข้าม

Point APoint BL∞​ distance​=(1,1)=(4,5)=max(∣4−1∣,∣5−1∣)=max(3,4)=4​

เมื่อไรควรใช้ L-infinity:

  • เมื่อความเบี่ยงเบนที่แย่ที่สุดในมิติใดมิติหนึ่งเป็นสิ่งสำคัญ
  • กระดานเกม (ขุนในหมากรุกเดินแบบ L-infinity: ก้าวหนึ่งไปทางไหนก็มีต้นทุน 1)
  • ค่าความคลาดเคลื่อนที่ยอมได้ในการผลิต (ทุกมิติต้องอยู่ในสเปก)

Cosine Similarity และ Cosine Distance

หัวข้อที่มีชื่อว่า “Cosine Similarity และ Cosine Distance”

Cosine similarity วัดมุมระหว่างเวกเตอร์สองตัว โดยไม่สนขนาดของมัน

cos_sim(a,b)=∥a∥2​∥b∥2​a⋅b​

ค่าอยู่ระหว่าง -1 (ชี้ไปทางตรงข้าม) ถึง +1 (ชี้ไปทางเดียวกัน) เวกเตอร์ที่ตั้งฉากกันมี cosine similarity เป็น 0

Cosine distance แปลงให้เป็นระยะทาง: cosine_distance = 1 - cosine_similarity มีค่าตั้งแต่ 0 (ทิศเดียวกันพอดี) ถึง 2 (ทิศตรงข้าม)

​a=(1,0)b=(1,1)cos_sim=1⋅2​1⋅1+0⋅1​=2​1​=0.707cos_dist=1−0.707=0.293​

ทำไม cosine จึงครอง NLP และ embedding: ในข้อความ ความยาวของเอกสารไม่ควรมีผลต่อความคล้าย เอกสารเรื่องแมวที่ยาวเป็นสองเท่าของอีกฉบับเรื่องแมว ก็ยังควร “คล้ายกัน” cosine similarity ไม่สนขนาด (ความยาว) และสนใจแค่ทิศทาง เอกสารสองฉบับที่มีการกระจายคำเหมือนกันแต่ยาวต่างกันชี้ไปทางเดียวกัน และได้ cosine similarity 1.0

เมื่อไรควรใช้ cosine similarity:

  • ความคล้ายของข้อความ (เวกเตอร์ TF-IDF, word embedding, sentence embedding)
  • โดเมนใดก็ตามที่ขนาดคือสัญญาณรบกวนและทิศทางคือสัญญาณ
  • ระบบแนะนำ (เวกเตอร์ความชอบของผู้ใช้)
  • การค้นหาด้วย embedding (ฐานข้อมูลเวกเตอร์แทบทั้งหมดใช้ cosine หรือ dot product)

Dot Product Similarity กับ Cosine Similarity

หัวข้อที่มีชื่อว่า “Dot Product Similarity กับ Cosine Similarity”

Dot product ของเวกเตอร์สองตัวคือ:

a⋅b​=a1​b1​+a2​b2​+⋯+an​bn​=∥a∥∥b∥cos(angle)​

Cosine similarity คือ dot product ที่หารด้วยขนาดทั้งสอง เมื่อเวกเตอร์ทั้งสองถูกทำให้ยาว 1 อยู่แล้ว dot product กับ cosine similarity เท่ากันพอดี

If ∥a∥=1 and ∥b∥=1:a⋅b=cos(angle between a and b)

เมื่อไรที่ต่างกัน: dot product รวมข้อมูลเรื่องขนาดไว้ด้วย เวกเตอร์ที่ขนาดใหญ่กว่าได้คะแนน dot product สูงกว่า เรื่องนี้สำคัญในระบบค้นคืนบางระบบที่คุณอยากให้ของที่ “ได้รับความนิยม” อยู่อันดับสูงกว่า ขนาดทำหน้าที่เป็นสัญญาณแฝงของคุณภาพหรือความสำคัญ

ในทางปฏิบัติ:

  • ใช้ cosine similarity เมื่อต้องการความคล้ายเชิงทิศทางล้วน ๆ
  • ใช้ dot product เมื่อขนาดมีความหมาย
  • ฐานข้อมูลเวกเตอร์หลายตัว (Pinecone, Weaviate, Qdrant) ให้คุณเลือกได้
  • ถ้า embedding ของคุณถูกทำให้ยาว 1 ด้วย L2 แล้ว จะเลือกแบบไหนก็ไม่ต่างกัน

ระยะทางแบบ Mahalanobis

หัวข้อที่มีชื่อว่า “ระยะทางแบบ Mahalanobis”

ระยะทางแบบยุคลิดมองทุกมิติเท่ากัน แต่ถ้าคุณลักษณะสัมพันธ์กันหรือมีสเกลต่างกัน L2 จะให้ผลที่ชวนเข้าใจผิด

ระยะทางแบบ Mahalanobis คิดถึงโครงสร้างความแปรปรวนร่วมของข้อมูล

dM​(x,y)=(x−y)TS−1(x−y)​

โดย S คือเมทริกซ์ความแปรปรวนร่วมของข้อมูล

โดยสัญชาตญาณ: ระยะทางแบบ Mahalanobis ขจัดสหสัมพันธ์และปรับสเกลข้อมูลก่อน (whitening) แล้วคำนวณระยะ L2 ในปริภูมิที่แปลงแล้วนั้น ถ้า S เป็นเมทริกซ์เอกลักษณ์ (คุณลักษณะไม่สัมพันธ์กันและมีความแปรปรวนหนึ่ง) ระยะทางแบบ Mahalanobis จะลดรูปเป็นระยะทางแบบยุคลิด

เมื่อไรควรใช้ระยะทางแบบ Mahalanobis:

  • ตรวจจับค่าผิดปกติ (จุดที่มีระยะ Mahalanobis จากค่าเฉลี่ยมากคือค่าผิดปกติ)
  • การจำแนกเมื่อคุณลักษณะมีสเกลและสหสัมพันธ์ต่างกัน
  • เมื่อมีข้อมูลพอที่จะประมาณเมทริกซ์ความแปรปรวนร่วมได้อย่างน่าเชื่อถือ
  • การควบคุมคุณภาพในการผลิต (การเฝ้าดูกระบวนการหลายตัวแปร)

Jaccard Similarity (สำหรับเซต)

หัวข้อที่มีชื่อว่า “Jaccard Similarity (สำหรับเซต)”

Jaccard similarity วัดการซ้อนทับกันระหว่างเซตสองเซต

J(A,B)=∣A∪B∣∣A∩B∣​

ค่าอยู่ระหว่าง 0 (ไม่ซ้อนทับเลย) ถึง 1 (เซตเหมือนกัน) Jaccard distance = 1 - Jaccard similarity

เมื่อไรควรใช้ Jaccard:

  • เทียบเซตของแท็ก หมวดหมู่ หรือคุณลักษณะ
  • ความคล้ายของเอกสารตามการมีอยู่ของคำ (ไม่ใช่ความถี่)
  • ตรวจหาข้อมูลที่เกือบซ้ำ (MinHash ประมาณค่า Jaccard)
  • เทียบเวกเตอร์คุณลักษณะแบบฐานสอง (ข้อมูลมี/ไม่มี)
  • ประเมินโมเดลการแบ่งส่วนภาพ (Intersection over Union = Jaccard)

Edit Distance (ระยะทางแบบ Levenshtein)

หัวข้อที่มีชื่อว่า “Edit Distance (ระยะทางแบบ Levenshtein)”

Edit distance นับจำนวนการดำเนินการทีละตัวอักษรที่น้อยที่สุดที่ต้องใช้เปลี่ยนสตริงหนึ่งไปเป็นอีกสตริงหนึ่ง การดำเนินการได้แก่ แทรก ลบ หรือแทนที่

คำนวณด้วยการโปรแกรมแบบพลวัต (dynamic programming) เติมเมทริกซ์ที่ช่อง (i,j) คือ edit distance ระหว่าง i ตัวอักษรแรกของสตริง A กับ j ตัวอักษรแรกของสตริง B

เมื่อไรควรใช้ edit distance:

  • ตรวจและแก้คำสะกดผิด
  • การจัดเรียงลำดับ DNA (โดยให้น้ำหนักกับการดำเนินการ)
  • การจับคู่สตริงแบบคลุมเครือ (fuzzy matching)
  • กำจัดข้อมูลข้อความที่ซ้ำและไม่เป็นระเบียบ

KL Divergence (ไม่ใช่ระยะทาง แต่ถูกใช้เหมือนระยะทาง)

หัวข้อที่มีชื่อว่า “KL Divergence (ไม่ใช่ระยะทาง แต่ถูกใช้เหมือนระยะทาง)”

KL divergence วัดว่าการแจกแจงความน่าจะเป็นหนึ่งต่างจากอีกการแจกแจงหนึ่งแค่ไหน อธิบายไปแล้วในบทที่ 09 แต่ควรอยู่ในการพูดคุยนี้ด้วย เพราะคนใช้มันเป็น “ระยะทาง” ทั้งที่มันไม่ใช่

DKL​(P∥Q)=x∑​p(x)logq(x)p(x)​

สมบัติสำคัญ: KL divergence ไม่สมมาตร

DKL​(P∥Q)=DKL​(Q∥P)

แปลว่ามันไม่ผ่านข้อกำหนดพื้นฐานของมาตรวัดระยะทาง และยังไม่เป็นไปตามอสมการสามเหลี่ยมด้วย มันคือ divergence ไม่ใช่ระยะทาง

KL ไปข้างหน้า (DKL​(P∥Q)) เป็นแบบ “หาค่าเฉลี่ย”: Q พยายามครอบคลุมทุกยอด (mode) ของ P KL ย้อนกลับ (DKL​(Q∥P)) เป็นแบบ “หายอด”: Q โฟกัสที่ยอดเดียวของ P

เมื่อคุณเห็น KL divergence:

  • VAE (พจน์ KL ใน ELBO ดันการแจกแจงแฝงเข้าหา prior)
  • Knowledge distillation (นักเรียนพยายามเลียนการแจกแจงของครู)
  • RLHF (บทลงโทษ KL รักษาให้โมเดลที่ fine-tune แล้วอยู่ใกล้โมเดลฐาน)
  • วิธี policy gradient (จำกัดการอัปเดต policy)

ระยะทางแบบ Wasserstein (Earth Mover’s Distance)

หัวข้อที่มีชื่อว่า “ระยะทางแบบ Wasserstein (Earth Mover’s Distance)”

ระยะทางแบบ Wasserstein วัด “งาน” น้อยที่สุดที่ต้องใช้เปลี่ยนการแจกแจงความน่าจะเป็นหนึ่งไปเป็นอีกการแจกแจงหนึ่ง ลองคิดว่า ถ้าการแจกแจงหนึ่งเป็นกองดิน และอีกการแจกแจงเป็นหลุม คุณต้องย้ายดินเท่าไรและไกลแค่ไหน

W(P,Q)=γinf​E[d(x,y)](over all transport plans γ)

(ค่าต่ำสุดเหนือแผนการขนย้าย γ ทุกแบบ)

สำหรับการแจกแจง 1 มิติ มันลดรูปเป็นปริพันธ์ของผลต่างสัมบูรณ์ของฟังก์ชันการแจกแจงสะสม (CDF):

W1​(P,Q)=∫∣CDFP​(x)−CDFQ​(x)∣dx

ทำไม Wasserstein จึงสำคัญ:

  • มันเป็นมาตรวัดแท้ (สมมาตร และเป็นไปตามอสมการสามเหลี่ยม)
  • มันให้ gradient ได้แม้การแจกแจงไม่ซ้อนทับกัน (ขณะที่ KL divergence พุ่งไปอนันต์)
  • สมบัตินี้ทำให้มันเป็นแกนกลางของ Wasserstein GAN (WGAN) ซึ่งแก้ปัญหาการเทรนที่ไม่เสถียรของ GAN ดั้งเดิม

เมื่อไรควรใช้ Wasserstein:

  • การเทรน GAN (WGAN, WGAN-GP)
  • เทียบการแจกแจงที่อาจไม่ซ้อนทับกัน
  • ปัญหาการขนส่งที่เหมาะสมที่สุด (optimal transport)
  • การค้นคืนภาพ (เทียบฮิสโทแกรมสี)

ทำไมงานต่างกันจึงต้องใช้ระยะทางต่างกัน

หัวข้อที่มีชื่อว่า “ทำไมงานต่างกันจึงต้องใช้ระยะทางต่างกัน”
งาน ระยะทางที่ดีที่สุด เพราะอะไร

เทียบพิกเซลของภาพ L2 ความสัมพันธ์เชิงพื้นที่สำคัญ คุณลักษณะมีสเกลเทียบกันได้

การซ้อนทับของเซต (แท็ก หมวดหมู่) Jaccard ข้อมูลเป็นเซตโดยธรรมชาติ ไม่ใช่เวกเตอร์

ความเชื่อมโยงกับฟังก์ชันความสูญเสีย

หัวข้อที่มีชื่อว่า “ความเชื่อมโยงกับฟังก์ชันความสูญเสีย”

ฟังก์ชันความสูญเสียคือฟังก์ชันระยะทางที่ใช้กับคำทำนายเทียบกับเป้าหมาย

ความเชื่อมโยงกับ regularization

หัวข้อที่มีชื่อว่า “ความเชื่อมโยงกับ regularization”

Regularization เพิ่มบทลงโทษที่เป็นนอร์มของน้ำหนักเข้าไปในฟังก์ชันความสูญเสีย

ทำไม L1 จึงให้ความเบาบางแต่ L2 ไม่ให้: นึกภาพบริเวณข้อจำกัดในปริภูมิน้ำหนัก 2 มิติ L1 เป็นข้าวหลามตัด L2 เป็นวงกลม เส้นชั้นของฟังก์ชันความสูญเสีย (วงรี) มีแนวโน้มสัมผัสข้าวหลามตัดที่มุม ซึ่งน้ำหนักตัวหนึ่งเป็นศูนย์ แต่สัมผัสวงกลมที่จุดเรียบ ซึ่งน้ำหนักทั้งสองไม่เป็นศูนย์

การค้นหาเพื่อนบ้านที่ใกล้ที่สุด

หัวข้อที่มีชื่อว่า “การค้นหาเพื่อนบ้านที่ใกล้ที่สุด”

ทุกฟังก์ชันระยะทางนำไปสู่ปัญหาการค้นหาเพื่อนบ้านที่ใกล้ที่สุด: เมื่อได้จุด query มา ให้หาจุดที่ใกล้ที่สุดในชุดข้อมูล

การค้นหาเพื่อนบ้านที่ใกล้ที่สุดแบบแม่นยำใช้ O(n⋅d) ต่อ query ในชุดข้อมูล n จุดที่มี d มิติ สำหรับชุดข้อมูลใหญ่ วิธีนี้ช้าเกินไป

อัลกอริทึม Approximate Nearest Neighbor (ANN) แลกความแม่นยำเล็กน้อยกับความเร็วที่เพิ่มขึ้นมหาศาล:

HNSW (Hierarchical Navigable Small World) คืออัลกอริทึมหลักในฐานข้อมูลเวกเตอร์สมัยใหม่ มันสร้างกราฟหลายชั้นที่แต่ละโหนดเชื่อมกับเพื่อนบ้านที่ใกล้ที่สุดโดยประมาณ การค้นหาเริ่มที่ชั้นบนสุด (เบาบาง กระโดดไกล) แล้วลงไปชั้นล่างสุด (หนาแน่น กระโดดสั้น)

ขั้นที่ 3: การค้นหาความคล้ายด้วย embedding

หัวข้อที่มีชื่อว่า “ขั้นที่ 3: การค้นหาความคล้ายด้วย embedding”

โค้ดมีการค้นหาความคล้ายด้วย embedding จำลองที่หา “เอกสาร” ที่คล้าย query ที่สุดโดยใช้ cosine similarity เทียบกับระยะ L2 แสดงให้เห็นว่าการจัดอันดับอาจต่างกัน

นำไปใช้ (Use It)

หัวข้อที่มีชื่อว่า “นำไปใช้ (Use It)”

การใช้งานจริงที่พบบ่อยที่สุด: หาของที่คล้ายกันในฐานข้อมูลเวกเตอร์

เมื่อคุณเรียก model.encode(text) แล้วค้นหาในฐานข้อมูลเวกเตอร์ นี่คือสิ่งที่เกิดขึ้นเบื้องหลัง โมเดล embedding จับคู่ข้อความไปเป็นเวกเตอร์ ฐานข้อมูลเวกเตอร์คำนวณ cosine similarity (หรือ dot product) ระหว่างเวกเตอร์ query กับเวกเตอร์ที่เก็บไว้ทุกตัว โดยใช้อัลกอริทึม ANN เพื่อไม่ต้องตรวจทุกตัว

แบบฝึกหัด

หัวข้อที่มีชื่อว่า “แบบฝึกหัด”

  1. คำนวณระยะ L1, L2 และ L-infinity ระหว่าง (1, 2, 3) กับ (4, 0, 6) ตรวจว่า L∞​≤L2​≤L1​ เป็นจริงเสมอสำหรับจุดทุกคู่ แล้วพิสูจน์ว่าทำไมลำดับนี้จึงรับประกันได้

  2. สร้างเวกเตอร์สองตัวที่ cosine similarity สูง (> 0.9) แต่ระยะ L2 มาก (> 10) อธิบายในเชิงเรขาคณิตว่าเกิดอะไรขึ้น จากนั้นสร้างเวกเตอร์สองตัวที่ cosine similarity ต่ำ (< 0.3) แต่ระยะ L2 น้อย (< 0.5)

  3. เขียนฟังก์ชันที่รับชุดข้อมูลและจุด query แล้วคืนเพื่อนบ้านที่ใกล้ที่สุดภายใต้ระยะ L1, L2, cosine และ Mahalanobis หาชุดข้อมูลที่ทั้งสี่ตัวเห็นไม่ตรงกันเลยว่าจุดไหนใกล้ที่สุด

  4. คำนวณระยะ Wasserstein ระหว่าง [0.5, 0.5, 0, 0] กับ [0, 0, 0.5, 0.5] ด้วยมือโดยใช้วิธี CDF จากนั้นคำนวณระหว่าง [0.25, 0.25, 0.25, 0.25] กับ [0, 0, 0.5, 0.5] ค่าไหนใหญ่กว่าและเพราะอะไร?

  5. เขียน MinHash เพื่อประมาณ Jaccard similarity สร้างเซตสุ่ม 100 เซต คำนวณ Jaccard แบบแม่นยำของทุกคู่ แล้วเทียบกับค่าประมาณจาก MinHash ที่ใช้ฟังก์ชัน hash 50, 100 และ 200 ตัว วาดกราฟความคลาดเคลื่อนของการประมาณ

คำใบ้

หัวข้อที่มีชื่อว่า “คำใบ้”

แบบฝึกหัดที่ 1 เวกเตอร์ผลต่างคือ (-3, 2, -3) จึงคำนวณนอร์มทั้งสามของเวกเตอร์นี้ด้วย l1_norm, l2_norm และ linf_norm สำหรับการพิสูจน์ ให้เทียบ ∣di​∣ ที่มากที่สุดกับผลรวมกำลังสอง และเทียบผลรวมกำลังสองกับกำลังสองของผลรวมค่าสัมบูรณ์

แบบฝึกหัดที่ 2 Cosine similarity ไม่สนความยาว จึงเริ่มจากเวกเตอร์สองตัวที่ชี้ไปเกือบทางเดียวกัน แล้วทำให้ตัวหนึ่งยาวกว่ามาก สำหรับกรณีที่สอง ใช้เวกเตอร์สั้น ๆ สองตัวใกล้จุดกำเนิดที่ชี้คนละทาง แล้วตรวจทั้งสองเงื่อนไขด้วย cosine_similarity และ l2_distance

แบบฝึกหัดที่ 3 เรียก find_nearest_neighbor(query, dataset, distance_fn) หนึ่งครั้งต่อ l1_distance, l2_distance, cosine_distance และ mahalanobis_distance demo_different_neighbors แสดงชุดข้อมูลที่มาตรวัดเห็นไม่ตรงกัน อ่านก่อน แล้วเปลี่ยนจุดจนคำตอบทั้งสี่ต่างกันหมด

แบบฝึกหัดที่ 4 เขียนผลรวมสะสมของการแจกแจงแต่ละตัว แล้วรวมผลต่างสัมบูรณ์ของผลรวมสะสมทั้งสอง ตรวจผลที่คำนวณด้วยมือทั้งสองด้วย wasserstein_1d(p, q) แล้วอธิบายค่าที่ใหญ่กว่าด้วยระยะที่มวลของความน่าจะเป็นต้องเคลื่อน

แบบฝึกหัดที่ 5 สำหรับฟังก์ชัน hash แต่ละตัว ลายเซ็น MinHash ของเซตคือค่า hash ที่น้อยที่สุดในบรรดาสมาชิก และสัดส่วนของฟังก์ชัน hash ที่สองเซตได้ค่าน้อยสุดเท่ากันคือค่าประมาณของ Jaccard similarity เทียบแต่ละค่าประมาณกับ jaccard_similarity ความคลาดเคลื่อนควรลดลงราว 1/k​ สำหรับฟังก์ชัน hash k ตัว

คำศัพท์สำคัญ

หัวข้อที่มีชื่อว่า “คำศัพท์สำคัญ”
คำศัพท์ ที่คนมักพูด ความหมายจริง
Norm (นอร์ม) “ขนาดของเวกเตอร์” ฟังก์ชันที่ส่งเวกเตอร์ไปเป็นสเกลาร์ที่ไม่ติดลบ เป็นไปตามอสมการสามเหลี่ยม ความเป็นเอกพันธ์สัมบูรณ์ และเป็นศูนย์เฉพาะเวกเตอร์ศูนย์
L1 norm “ระยะแมนฮัตตัน” ผลรวมของค่าสัมบูรณ์ขององค์ประกอบ ทำให้เกิดความเบาบางใน optimization ทนต่อค่าผิดปกติ
L2 norm “ระยะยุคลิด” รากที่สองของผลรวมกำลังสองขององค์ประกอบ ระยะทางเส้นตรงในปริภูมิยุคลิด
Lp norm “นอร์มแบบทั่วไป” รากที่ p ของผลรวมกำลัง p ของค่าสัมบูรณ์ขององค์ประกอบ L1 และ L2 เป็นกรณีพิเศษ
L-infinity norm “นอร์มค่ามากสุด” หรือ “ระยะเชบีเชฟ” ค่าสัมบูรณ์ที่มากที่สุดขององค์ประกอบ เป็นลิมิตของ Lp เมื่อ p เข้าใกล้อนันต์
Cosine similarity “มุมระหว่างเวกเตอร์” dot product หารด้วยขนาดทั้งสอง มีค่าตั้งแต่ -1 ถึง +1 ไม่สนความยาวของเวกเตอร์
Cosine distance “1 ลบ cosine similarity” แปลง cosine similarity เป็นระยะทาง มีค่าตั้งแต่ 0 ถึง 2
Dot product “cosine ที่ไม่ได้ทำให้เป็นมาตรฐาน” ผลรวมของผลคูณทีละองค์ประกอบ เท่ากับ cosine similarity คูณขนาดทั้งสอง
Mahalanobis distance “ระยะทางที่คิดถึงสหสัมพันธ์” ระยะ L2 ในปริภูมิที่ทำ whitening แล้ว (ขจัดสหสัมพันธ์และปรับสเกล) ด้วยเมทริกซ์ความแปรปรวนร่วมของข้อมูล
Jaccard similarity “การซ้อนทับของเซต” ขนาดของส่วนร่วมหารด้วยขนาดของผลรวม ใช้กับเซต ไม่ใช่เวกเตอร์
Edit distance “ระยะ Levenshtein” จำนวนการแทรก ลบ และแทนที่ที่น้อยที่สุดเพื่อเปลี่ยนสตริงหนึ่งไปเป็นอีกสตริงหนึ่ง
KL divergence “ระยะห่างระหว่างการแจกแจง” ไม่ใช่ระยะทางแท้ (ไม่สมมาตร) วัดจำนวนบิตที่เพิ่มขึ้นจากการใช้ Q เข้ารหัส P
Wasserstein distance “Earth mover’s distance” งานน้อยที่สุดในการขนย้ายมวลจากการแจกแจงหนึ่งไปอีกการแจกแจงหนึ่ง เป็นมาตรวัดแท้
Approximate nearest neighbor “การค้นหาแบบ ANN” อัลกอริทึม (HNSW, LSH, IVF) ที่หาจุดที่ใกล้ที่สุดโดยประมาณได้เร็วกว่าการค้นหาแบบแม่นยำมาก
HNSW “อัลกอริทึมของฐานข้อมูลเวกเตอร์” กราฟ Hierarchical Navigable Small World กราฟหลายชั้นสำหรับค้นหาเพื่อนบ้านใกล้สุดโดยประมาณอย่างรวดเร็ว
L1 regularization “Lasso” บวกนอร์ม L1 ของน้ำหนักเข้าไปใน loss ดันน้ำหนักให้เป็นศูนย์ (ความเบาบาง)
L2 regularization “Ridge” หรือ “weight decay” บวกกำลังสองของนอร์ม L2 ของน้ำหนักเข้าไปใน loss หดน้ำหนักเข้าหาศูนย์โดยไม่เบาบาง
Elastic Net “L1 + L2” รวม L1 และ L2 regularization รับมือกลุ่มคุณลักษณะที่สัมพันธ์กันได้ดีกว่าแบบใดแบบหนึ่ง
