> สถิติคือวิธีที่คุณรู้ว่าโมเดลใช้ได้จริง หรือแค่ฟลุก

**ประเภท:** ลงมือสร้าง (Build)
**ภาษา:** Python, TypeScript
**ความรู้ที่ควรมีก่อน:** Phase 1 บทที่ 06 (ความน่าจะเป็นและการแจกแจง), 07 (ทฤษฎีบทของเบย์)
**เวลา:** ~120 นาที

## สิ่งที่จะได้เรียนรู้

- คำนวณสถิติเชิงพรรณนา สหสัมพันธ์แบบเพียร์สัน/สเปียร์แมน และเมทริกซ์ความแปรปรวนร่วมตั้งแต่ศูนย์
- ทำการทดสอบสมมติฐาน (t-test, chi-squared) และตีความ p-value กับช่วงความเชื่อมั่นได้ถูกต้อง
- ใช้ bootstrap resampling สร้างช่วงความเชื่อมั่นของตัววัดใดก็ได้ โดยไม่ต้องสมมติรูปแบบการแจกแจง
- แยกนัยสำคัญทางสถิติออกจากนัยสำคัญในทางปฏิบัติด้วยขนาดผล (effect size)

## ปัญหา

คุณเทรนโมเดลสองตัว โมเดล A ได้ 0.87 บนชุดทดสอบ โมเดล B ได้ 0.89 คุณ deploy โมเดล B สามสัปดาห์ต่อมา ตัวชี้วัดในระบบจริงแย่กว่าเดิม เกิดอะไรขึ้น?

โมเดล B ไม่ได้ดีกว่าโมเดล A จริง ผลต่าง 0.02 คือสัญญาณรบกวน ชุดทดสอบของคุณเล็กเกินไป หรือความแปรปรวนสูงเกินไป หรือทั้งสองอย่าง คุณส่งความสุ่มที่แต่งตัวเป็นการปรับปรุงออกไป

เรื่องนี้เกิดขึ้นตลอดเวลา อันดับใน Kaggle ที่สลับกันวุ่นวาย เปเปอร์ที่ทำซ้ำผลไม่ได้ A/B test ที่ประกาศผู้ชนะจากตัวอย่างไม่กี่ร้อยตัว ต้นเหตุเหมือนกันทุกครั้ง: มีคนข้ามเรื่องสถิติไป

สถิติให้เครื่องมือแยกสัญญาณออกจากสัญญาณรบกวน มันบอกว่าเมื่อไรผลต่างเป็นของจริง คุณควรมั่นใจแค่ไหน และต้องใช้ข้อมูลเท่าไรก่อนจะเชื่อผลได้ ทุก pipeline ของ ML ทุกการเปรียบเทียบโมเดล และทุกการทดลองต้องใช้สถิติ ถ้าไม่มีมัน คุณก็แค่เดา

## แนวคิด

### สถิติเชิงพรรณนา: สรุปข้อมูลของคุณ

ก่อนจะสร้างโมเดลอะไร คุณต้องรู้ว่าข้อมูลหน้าตาเป็นอย่างไร สถิติเชิงพรรณนา (descriptive statistics) บีบชุดข้อมูลให้เหลือตัวเลขไม่กี่ตัวที่จับรูปร่างของมันไว้

**ค่ากลาง (central tendency)** ตอบคำถามว่า "ตรงกลางอยู่ที่ไหน?"

```
ค่าเฉลี่ย (mean):   ผลรวมของทุกค่า / จำนวน
        mu = (1/n) * sum(x_i)

มัธยฐาน (median): ค่าตรงกลางเมื่อเรียงแล้ว
        ทนต่อค่าผิดปกติ ถ้าข้อมูลคือ [1, 2, 3, 4, 1000] ค่าเฉลี่ยคือ 202
        แต่มัธยฐานคือ 3

ฐานนิยม (mode):   ค่าที่พบบ่อยที่สุด
        มีประโยชน์กับข้อมูลเชิงหมวดหมู่ สำหรับข้อมูลต่อเนื่องแทบไม่ให้ข้อมูลอะไร
```

ค่าเฉลี่ยคือจุดสมดุล มัธยฐานคือจุดกึ่งกลาง เมื่อสองค่านี้ห่างกัน การแจกแจงของคุณเบ้ การแจกแจงรายได้มี $\text{mean} \gg \text{median}$ (เบ้ขวาจากมหาเศรษฐี) การแจกแจงของ loss ระหว่างเทรนมักมี $\text{mean} \ll \text{median}$ (เบ้ซ้ายจากตัวอย่างที่ง่าย)

**การกระจาย (spread)** ตอบคำถามว่า "ข้อมูลกระจายแค่ไหน?"

```
ความแปรปรวน:   ค่าเฉลี่ยของกำลังสองของระยะห่างจากค่าเฉลี่ย
            sigma^2 = (1/n) * sum((x_i - mu)^2)

ส่วนเบี่ยงเบนมาตรฐาน:  รากที่สองของความแปรปรวน
                     sigma = sqrt(sigma^2)
                     หน่วยเดียวกับข้อมูล จึงตีความง่ายกว่า

พิสัย (range):      max - min
            อ่อนไหวต่อค่าผิดปกติ แทบไม่มีประโยชน์เมื่อใช้ตัวเดียว

IQR:        Q3 - Q1 (พิสัยระหว่างควอร์ไทล์)
            พิสัยของข้อมูล 50% ตรงกลาง
            ทนต่อค่าผิดปกติ ใช้กับ box plot และการตรวจหาค่าผิดปกติ
```

**เปอร์เซ็นไทล์ (percentile)** แบ่งข้อมูลที่เรียงแล้วเป็น 100 ส่วนเท่ากัน เปอร์เซ็นไทล์ที่ 25 (Q1) แปลว่าค่า 25% อยู่ต่ำกว่าจุดนี้ เปอร์เซ็นไทล์ที่ 50 คือมัธยฐาน เปอร์เซ็นไทล์ที่ 75 คือ Q3

```
สำหรับเฝ้าดู latency:
  P50 = latency มัธยฐาน          (ประสบการณ์ของผู้ใช้ทั่วไป)
  P95 = เปอร์เซ็นไทล์ที่ 95       (แย่แต่ยังไม่ใช่กรณีเลวร้ายสุด)
  P99 = เปอร์เซ็นไทล์ที่ 99       (latency ที่หาง มักเป็น 10 เท่าของมัธยฐาน)
```

ใน ML คุณสนใจเปอร์เซ็นไทล์สำหรับ latency ตอน inference การแจกแจงความมั่นใจของคำทำนาย และความเข้าใจการแจกแจงของความคลาดเคลื่อน โมเดลที่ความคลาดเคลื่อนเฉลี่ยต่ำแต่ความคลาดเคลื่อน P99 แย่มากอาจใช้ไม่ได้เลยในงานที่ความปลอดภัยสำคัญ

**สถิติของตัวอย่างกับของประชากร** เมื่อคำนวณความแปรปรวนจากตัวอย่าง ให้หารด้วย $(n-1)$ แทน $n$ นี่คือการแก้ของเบสเซล (Bessel's correction) มันชดเชยข้อเท็จจริงที่ว่าค่าเฉลี่ยของตัวอย่างไม่ใช่ค่าเฉลี่ยจริงของประชากร ถ้าใช้ $n$ เป็นตัวส่วน คุณจะประมาณความแปรปรวนจริงต่ำเกินไปอย่างเป็นระบบ ถ้าใช้ $(n-1)$ ค่าประมาณจะไม่เอนเอียง (unbiased)

```math
\begin{aligned}
\text{Population variance:} \quad \sigma^2 &= \frac{1}{N} \sum (x_i - \mu)^2 \\
\text{Sample variance:} \quad s^2 &= \frac{1}{n-1} \sum (x_i - \bar{x})^2
\end{aligned}
```

(บรรทัดแรกคือความแปรปรวนของประชากร บรรทัดที่สองคือความแปรปรวนของตัวอย่าง)

ในทางปฏิบัติ: ถ้า $n$ ใหญ่ (ตัวอย่างหลักพัน) ความต่างแทบไม่มีผล ถ้า $n$ เล็ก (ตัวอย่างหลักสิบ) มันมีผล

### สหสัมพันธ์: ตัวแปรขยับไปด้วยกันอย่างไร

สหสัมพันธ์ (correlation) วัดความแรงและทิศทางของความสัมพันธ์เชิงเส้นระหว่างตัวแปรสองตัว

**สัมประสิทธิ์สหสัมพันธ์แบบเพียร์สัน** วัดความสัมพันธ์เชิงเส้น:

```
r = sum((x_i - x_bar)(y_i - y_bar)) / (n * s_x * s_y)

r = +1:  ความสัมพันธ์เชิงเส้นทางบวกสมบูรณ์
r = -1:  ความสัมพันธ์เชิงเส้นทางลบสมบูรณ์
r =  0:  ไม่มีความสัมพันธ์เชิงเส้น (แต่อาจมีแบบไม่เชิงเส้น!)

ช่วง: [-1, 1]
```

เพียร์สันสมมติว่าความสัมพันธ์เป็นเชิงเส้น และตัวแปรทั้งสองมีการแจกแจงใกล้เคียงปกติ มันอ่อนไหวต่อค่าผิดปกติ จุดสุดโต่งจุดเดียวลาก $r$ จาก 0.1 ไปเป็น 0.9 ได้

**สหสัมพันธ์อันดับแบบสเปียร์แมน** วัดความสัมพันธ์แบบทางเดียว (monotonic):

```
1. แทนแต่ละค่าด้วยอันดับของมัน (1, 2, 3, ...)
2. คำนวณสหสัมพันธ์แบบเพียร์สันบนอันดับ

สเปียร์แมนจับความสัมพันธ์แบบทางเดียวได้ทุกแบบ ไม่ใช่แค่เชิงเส้น
ถ้า y = x^3 เพียร์สันให้ r < 1 แต่สเปียร์แมนให้ rho = 1
```

**ใช้แบบไหนเมื่อไร:**

```
เพียร์สัน:    ตัวแปรทั้งสองต่อเนื่องและใกล้เคียงการแจกแจงปกติ
            คุณสนใจความสัมพันธ์เชิงเส้นโดยเฉพาะ
            ไม่มีค่าผิดปกติสุดโต่ง

สเปียร์แมน:   ข้อมูลเชิงอันดับ (การจัดอันดับ คะแนน)
            ข้อมูลไม่ได้แจกแจงแบบปกติ
            คุณสงสัยว่ามีความสัมพันธ์แบบทางเดียวแต่ไม่เชิงเส้น
            มีค่าผิดปกติ
```

**กฎทอง:** สหสัมพันธ์ไม่ได้บอกความเป็นเหตุเป็นผล ยอดขายไอศกรีมกับการเสียชีวิตจากการจมน้ำสัมพันธ์กันเพราะทั้งคู่เพิ่มขึ้นในฤดูร้อน ความแม่นยำของโมเดลกับจำนวนพารามิเตอร์สัมพันธ์กัน แต่การเพิ่มพารามิเตอร์ไม่ได้ทำให้แม่นขึ้นโดยอัตโนมัติ (ดู: overfitting)

### เมทริกซ์ความแปรปรวนร่วม

ความแปรปรวนร่วมระหว่างตัวแปรสองตัววัดว่ามันแปรผันไปด้วยกันอย่างไร:

```
Cov(X, Y) = (1/n) * sum((x_i - x_bar)(y_i - y_bar))

Cov(X, Y) > 0:  X และ Y มักเพิ่มขึ้นด้วยกัน
Cov(X, Y) < 0:  เมื่อ X เพิ่ม Y มักลดลง
Cov(X, Y) = 0:  ไม่มีการขยับร่วมกันเชิงเส้น
```

สำหรับ $d$ คุณลักษณะ เมทริกซ์ความแปรปรวนร่วม $C$ คือเมทริกซ์ $d \times d$ ที่ $C[i][j] = \mathop{\mathrm{Cov}}(\text{feature}_i, \text{feature}_j)$ ช่องบนเส้นทแยงมุม $C[i][i]$ คือความแปรปรวนของแต่ละคุณลักษณะ

```
C = | Var(x1)      Cov(x1,x2)  Cov(x1,x3) |
    | Cov(x2,x1)  Var(x2)      Cov(x2,x3) |
    | Cov(x3,x1)  Cov(x3,x2)  Var(x3)     |

สมบัติ:
  - สมมาตร: C[i][j] = C[j][i]
  - กึ่งบวกแน่นอน: ค่าลักษณะเฉพาะทุกตัว >= 0
  - เส้นทแยงมุม = ความแปรปรวน
  - นอกเส้นทแยงมุม = ความแปรปรวนร่วม
```

**ความเชื่อมโยงกับ PCA** PCA แยกค่าลักษณะเฉพาะของเมทริกซ์ความแปรปรวนร่วม เวกเตอร์ลักษณะเฉพาะคือองค์ประกอบหลัก (ทิศที่ความแปรปรวนมากที่สุด) ค่าลักษณะเฉพาะบอกว่าแต่ละองค์ประกอบเก็บความแปรปรวนได้เท่าไร นี่คือสิ่งที่บทที่ 10 อธิบายไปแล้ว แต่ตอนนี้คุณเห็นว่าทำไมเมทริกซ์ความแปรปรวนร่วมจึงเป็นสิ่งที่ควรแยก: มันเก็บความสัมพันธ์เชิงเส้นของทุกคู่ในข้อมูลไว้

**ความเชื่อมโยงกับสหสัมพันธ์** เมทริกซ์สหสัมพันธ์คือเมทริกซ์ความแปรปรวนร่วมของตัวแปรที่ปรับมาตรฐานแล้ว (หารแต่ละตัวด้วยส่วนเบี่ยงเบนมาตรฐานของมัน) สหสัมพันธ์ทำให้ความแปรปรวนร่วมเป็นมาตรฐานจนทุกค่าอยู่ใน $[-1, 1]$

### การทดสอบสมมติฐาน

การทดสอบสมมติฐาน (hypothesis testing) คือกรอบการตัดสินใจภายใต้ความไม่แน่นอน คุณเริ่มจากข้อกล่าวอ้าง เก็บข้อมูล แล้วดูว่าข้อมูลสอดคล้องกับข้อกล่าวอ้างนั้นหรือไม่

**การตั้งต้น:**

```
สมมติฐานว่าง (H0):        ข้อสมมติตั้งต้น มักเป็น "ไม่มีผล"
สมมติฐานทางเลือก (H1):     สิ่งที่คุณพยายามแสดงให้เห็น

ตัวอย่าง:
  H0: โมเดล A และโมเดล B มีความแม่นยำเท่ากัน
  H1: โมเดล B แม่นยำกว่าโมเดล A
```

**p-value** คือความน่าจะเป็นที่จะเห็นข้อมูลสุดโต่งเท่ากับที่สังเกตได้หรือมากกว่า โดยสมมติว่า H0 เป็นจริง มันไม่ใช่ความน่าจะเป็นที่ H0 เป็นจริง นี่คือความเข้าใจผิดที่พบบ่อยที่สุดในสถิติ

```
p-value = P(ข้อมูลสุดโต่งขนาดนี้ | H0 เป็นจริง)

ถ้า p-value < alpha (ปกติ 0.05):
    ปฏิเสธ H0 ผลนี้ "มีนัยสำคัญทางสถิติ"
ถ้า p-value >= alpha:
    ปฏิเสธ H0 ไม่ได้ คุณมีหลักฐานไม่พอ
    นี่ไม่ได้แปลว่า H0 เป็นจริง
```

**ช่วงความเชื่อมั่น (confidence interval)** ให้ช่วงของค่าที่เป็นไปได้ของพารามิเตอร์:

```
ช่วงความเชื่อมั่น 95% ของค่าเฉลี่ย:
    x_bar +/- z * (s / sqrt(n))

โดย z = 1.96 สำหรับความเชื่อมั่น 95%

การตีความ: ถ้าทำการทดลองนี้ซ้ำหลายครั้ง 95% ของช่วงที่คำนวณได้
จะครอบค่าเฉลี่ยจริง มันไม่ได้แปลว่ามีความน่าจะเป็น 95%
ที่ค่าเฉลี่ยจริงอยู่ในช่วงเฉพาะช่วงนี้
```

ความกว้างของช่วงความเชื่อมั่นบอกเรื่องความเที่ยง (precision) ช่วงกว้างแปลว่าความไม่แน่นอนสูง ช่วงแคบแปลว่าค่าประมาณเที่ยง (แต่ไม่จำเป็นต้องแม่น ถ้าข้อมูลเอนเอียง)

### t-test

t-test เปรียบเทียบค่าเฉลี่ย มีหลายแบบ

**One-sample t-test:** ค่าเฉลี่ยของประชากรต่างจากค่าที่ตั้งสมมติฐานไว้หรือไม่?

```math
\begin{aligned}
t &= \frac{\bar{x} - \mu_0}{s / \sqrt{n}} \\[4pt]
\text{degrees of freedom} &= n - 1
\end{aligned}
```

(degrees of freedom คือองศาเสรี)

**Two-sample t-test (อิสระต่อกัน):** ค่าเฉลี่ยของสองกลุ่มต่างกันหรือไม่?

```
t = (x_bar_1 - x_bar_2) / sqrt(s1^2/n1 + s2^2/n2)

นี่คือ t-test ของ Welch ซึ่งไม่สมมติว่าความแปรปรวนเท่ากัน
ใช้แบบของ Welch เสมอ เว้นแต่มีเหตุผลเฉพาะที่จะสมมติว่าความแปรปรวนเท่ากัน
```

**Paired t-test:** เมื่อการวัดมาเป็นคู่ (โมเดลเดียวกันวัดบน data split เดียวกัน):

```
คำนวณ d_i = x_i - y_i ของแต่ละคู่
แล้วทำ one-sample t-test กับค่า d_i เทียบกับ mu_0 = 0
```

ใน ML paired t-test พบบ่อย: คุณรันโมเดลทั้งสองบน 10 fold ของ cross-validation ชุดเดียวกัน แล้วเทียบคะแนนทีละคู่

### Chi-squared Test

Chi-squared test ตรวจว่าความถี่ที่สังเกตได้ตรงกับความถี่ที่คาดหวังหรือไม่ ใช้กับข้อมูลเชิงหมวดหมู่

```
chi^2 = sum((observed - expected)^2 / expected)

ตัวอย่าง: การแจกแจงผลลัพธ์ของโมเดลภาษาตรงกับ
การแจกแจงของข้อมูลเทรนในแต่ละหมวดหรือไม่?

หมวด        สังเกตได้   คาดหวัง
Positive       120        100
Negative        80        100
chi^2 = (120-100)^2/100 + (80-100)^2/100 = 4 + 4 = 8

ที่ 1 องศาเสรี chi^2 = 8 ให้ p < 0.005
ความต่างนี้มีนัยสำคัญ
```

### A/B Testing สำหรับโมเดล ML

A/B testing ใน ML ไม่เหมือน A/B testing ของเว็บ การเปรียบเทียบโมเดลมีความท้าทายเฉพาะ:

```
1. ชุดทดสอบเดียวกัน:   โมเดลทั้งสองต้องวัดบนข้อมูลชุดเดียวกันทุกประการ
                     ชุดทดสอบต่างกันทำให้การเปรียบเทียบไร้ความหมาย

2. หลายตัวชี้วัด:      ความแม่นยำอย่างเดียวไม่พอ ต้องมี precision,
                     recall, F1, latency และตัวชี้วัดความเป็นธรรม

3. ความแปรปรวน:       ใช้ cross-validation หรือ bootstrap ประมาณ
                     ความแปรปรวนของแต่ละตัวชี้วัด ไม่ใช่แค่ค่าประมาณแบบจุด

4. ข้อมูลรั่ว:           ถ้าชุดทดสอบถูกใช้ระหว่างเลือกโมเดล
                     การเปรียบเทียบจะเอนเอียง ให้กันชุดทดสอบสุดท้ายไว้
```

**ขั้นตอน:**

```
1. กำหนดตัวชี้วัดและระดับนัยสำคัญ (alpha = 0.05)
2. รันโมเดลทั้งสองบน k-fold cross-validation split ชุดเดียวกัน
3. เก็บคะแนนเป็นคู่: [(a1, b1), (a2, b2), ..., (ak, bk)]
4. คำนวณผลต่าง: d_i = b_i - a_i
5. ทำ paired t-test กับผลต่าง
6. ตรวจ: ค่าเฉลี่ยของผลต่างต่างจาก 0 อย่างมีนัยสำคัญหรือไม่?
7. คำนวณช่วงความเชื่อมั่นของค่าเฉลี่ยของผลต่าง
8. คำนวณขนาดผล (Cohen's d) เพื่อตัดสินนัยสำคัญในทางปฏิบัติ
```

### นัยสำคัญทางสถิติกับนัยสำคัญในทางปฏิบัติ

ผลหนึ่งอาจมีนัยสำคัญทางสถิติแต่ไม่มีความหมายในทางปฏิบัติ เมื่อข้อมูลมากพอ แม้ผลต่างเล็กน้อยก็กลายเป็นมีนัยสำคัญทางสถิติ

```
ตัวอย่าง:
  ความแม่นยำโมเดล A: 0.9234
  ความแม่นยำโมเดล B: 0.9237
  n = 1,000,000 ตัวอย่างทดสอบ
  p-value = 0.001

มีนัยสำคัญทางสถิติ? ใช่
มีนัยสำคัญในทางปฏิบัติ? การปรับปรุง 0.03% ไม่คุ้มกับ
ต้นทุนทางวิศวกรรมในการ deploy โมเดลใหม่
```

**ขนาดผล (effect size)** วัดว่าผลต่างใหญ่แค่ไหน โดยไม่ขึ้นกับขนาดตัวอย่าง:

```math
\begin{aligned}
\text{Cohen's } d &= \frac{\text{mean}_1 - \text{mean}_2}{\text{pooled\_std}} \\[4pt]
d &= 0.2: \quad \text{small effect} \\
d &= 0.5: \quad \text{medium effect} \\
d &= 0.8: \quad \text{large effect}
\end{aligned}
```

(pooled_std คือส่วนเบี่ยงเบนมาตรฐานรวม d = 0.2 คือผลเล็ก 0.5 คือผลปานกลาง และ 0.8 คือผลใหญ่)

รายงานทั้ง p-value และขนาดผลเสมอ p-value บอกว่าผลต่างเป็นของจริงไหม ขนาดผลบอกว่ามันสำคัญไหม

### ปัญหาการเปรียบเทียบหลายครั้ง

เมื่อคุณทดสอบสมมติฐานหลายข้อ บางข้อจะ "มีนัยสำคัญ" โดยบังเอิญ ถ้าทดสอบ 20 อย่างที่ $\alpha = 0.05$ คุณคาดว่าจะได้ผลบวกลวง 1 ข้อ แม้จะไม่มีอะไรเป็นจริงเลย

```
P(มีผลบวกลวงอย่างน้อยหนึ่งข้อ) = 1 - (1 - alpha)^m

m = 20 การทดสอบ, alpha = 0.05:
P(ผลบวกลวง) = 1 - 0.95^20 = 0.64

คุณมีโอกาส 64% ที่จะได้ผลบวกลวงอย่างน้อยหนึ่งข้อ
```

**การแก้ของ Bonferroni (Bonferroni correction):** หาร $\alpha$ ด้วยจำนวนการทดสอบ

```
alpha ที่ปรับแล้ว = alpha / m = 0.05 / 20 = 0.0025

ปฏิเสธ H0 ก็ต่อเมื่อ p-value < 0.0025
อนุรักษ์นิยมแต่ง่าย ใช้ได้เมื่อการทดสอบเป็นอิสระต่อกัน
```

ใน ML เรื่องนี้สำคัญเมื่อคุณเปรียบเทียบโมเดลบนหลายตัวชี้วัด ทดสอบการตั้งค่า hyperparameter หลายแบบ หรือประเมินบนหลายชุดข้อมูล

### วิธี Bootstrap

Bootstrapping ประมาณการแจกแจงการสุ่มตัวอย่าง (sampling distribution) ของสถิติด้วยการสุ่มข้อมูลของคุณซ้ำแบบใส่คืน ไม่ต้องสมมติอะไรเกี่ยวกับการแจกแจงเบื้องหลัง

**อัลกอริทึม:**

```
1. คุณมีจุดข้อมูล n จุด
2. สุ่ม n ตัวอย่างแบบใส่คืน (บางจุดปรากฏหลายครั้ง
   บางจุดไม่ปรากฏเลย)
3. คำนวณสถิติของคุณบนตัวอย่าง bootstrap นี้
4. ทำซ้ำ B ครั้ง (ปกติ B = 1000 ถึง 10000)
5. การแจกแจงของสถิติ bootstrap ประมาณ
   การแจกแจงการสุ่มตัวอย่างได้
```

**ช่วงความเชื่อมั่นแบบ bootstrap (วิธีเปอร์เซ็นไทล์):**

```
เรียงสถิติ bootstrap ทั้ง B ค่า
95% CI = [เปอร์เซ็นไทล์ที่ 2.5, เปอร์เซ็นไทล์ที่ 97.5]
```

**ทำไม bootstrap จึงสำคัญกับ ML:**

```
- ความแม่นยำบนชุดทดสอบเป็นค่าประมาณแบบจุด bootstrap ให้
  ช่วงความเชื่อมั่นกับคุณ
- คุณสมมติไม่ได้ว่าการแจกแจงของตัวชี้วัดเป็นแบบปกติ (โดยเฉพาะ
  AUC, F1, precision at k)
- Bootstrap ใช้ได้กับทุกสถิติ: มัธยฐาน อัตราส่วนของค่าเฉลี่ยสองตัว
  ผลต่างของ AUC ระหว่างโมเดลสองตัว
- ไม่ต้องมีสูตรแบบปิด
```

**Bootstrap สำหรับเปรียบเทียบโมเดล:**

```
1. คุณมีคำทำนายจากโมเดล A และโมเดล B บนชุดทดสอบเดียวกัน
2. ในแต่ละรอบของ bootstrap:
   a. สุ่มดัชนีของชุดทดสอบซ้ำแบบใส่คืน
   b. คำนวณ metric_A และ metric_B บนชุดที่สุ่มซ้ำ
   c. เก็บ diff = metric_B - metric_A
3. 95% CI ของผลต่าง:
   [เปอร์เซ็นไทล์ที่ 2.5 ของ diffs, เปอร์เซ็นไทล์ที่ 97.5 ของ diffs]
4. ถ้า CI ไม่ครอบ 0 ผลต่างนั้นมีนัยสำคัญ
```

วิธีนี้ทนทานกว่า paired t-test เพราะไม่สมมติอะไรเรื่องการแจกแจง

### การทดสอบแบบอิงพารามิเตอร์กับแบบไม่อิงพารามิเตอร์

**การทดสอบแบบอิงพารามิเตอร์ (parametric)** สมมติการแจกแจงแบบเฉพาะ (มักเป็นแบบปกติ):

```
t-test:         สมมติว่าข้อมูลแจกแจงแบบปกติ (หรือ n ใหญ่ตาม CLT)
ANOVA:          สมมติความเป็นปกติและความแปรปรวนเท่ากัน
Pearson r:      สมมติการแจกแจงปกติสองตัวแปร
```

**การทดสอบแบบไม่อิงพารามิเตอร์ (non-parametric)** ไม่สมมติเรื่องการแจกแจง:

```
Mann-Whitney U:     เทียบสองกลุ่ม (ใช้แทน independent t-test)
Wilcoxon signed-rank: เทียบข้อมูลที่เป็นคู่ (ใช้แทน paired t-test)
Spearman rho:       สหสัมพันธ์บนอันดับ (ใช้แทน Pearson)
Kruskal-Wallis:     เทียบหลายกลุ่ม (ใช้แทน ANOVA)
```

**เมื่อไรควรใช้แบบไม่อิงพารามิเตอร์:**

```
- ขนาดตัวอย่างเล็ก (n < 30) และข้อมูลไม่ปกติอย่างชัดเจน
- ข้อมูลเชิงอันดับ (คะแนน การจัดอันดับ)
- มีค่าผิดปกติรุนแรงที่ตัดทิ้งไม่ได้
- การแจกแจงเบ้
```

**เมื่อไรควรใช้แบบอิงพารามิเตอร์:**

```
- ขนาดตัวอย่างใหญ่ (CLT ทำให้สถิติทดสอบใกล้เคียงการแจกแจงปกติ)
- ข้อมูลค่อนข้างสมมาตรและไม่มีค่าผิดปกติสุดโต่ง
- มีอำนาจทางสถิติมากกว่า (ตรวจจับความต่างที่มีจริงได้ดีกว่า)
```

ในการทดลอง ML ปกติคุณมี $n$ เล็ก (5 หรือ 10 fold ของ cross-validation) การทดสอบแบบไม่อิงพารามิเตอร์อย่าง Wilcoxon signed-rank จึงมักเหมาะกว่า t-test

### ทฤษฎีบทลิมิตสู่ส่วนกลาง: ผลในทางปฏิบัติ

CLT บอกว่าการแจกแจงของค่าเฉลี่ยตัวอย่างเข้าใกล้การแจกแจงปกติเมื่อ $n$ โตขึ้น ไม่ว่าการแจกแจงของประชากรเบื้องหลังจะเป็นแบบไหน

```
ถ้า X_1, X_2, ..., X_n เป็น iid ที่มีค่าเฉลี่ย mu และความแปรปรวน sigma^2:

    X_bar ~ Normal(mu, sigma^2 / n)    เมื่อ n -> อนันต์

ใช้ได้เมื่อ n >= 30 ในกรณีส่วนใหญ่
สำหรับการแจกแจงที่เบ้มาก อาจต้องใช้ n >= 100
```

**ทำไมเรื่องนี้จึงสำคัญกับ ML:**

```
1. ให้เหตุผลรองรับช่วงความเชื่อมั่นและ t-test บนตัวชี้วัดที่รวมแล้ว
2. อธิบายว่าทำไมการเฉลี่ยข้าม fold ของ cross-validation จึงได้
   ค่าประมาณที่เสถียร แม้แต่ละ fold จะแกว่งมาก
3. Mini-batch gradient descent ได้ผลเพราะ gradient เฉลี่ย
   ของ batch ประมาณ gradient จริงได้ (CLT ในการใช้งาน)
4. วิธี ensemble: การเฉลี่ยคำทำนายจากหลายโมเดลให้
   ผลที่เสถียรกว่าโมเดลเดี่ยวตัวใด
```

**สิ่งที่ CLT ไม่ได้ทำ:**

```
- ไม่ได้ทำให้ข้อมูลของคุณเป็นแบบปกติ มันทำให้ค่าเฉลี่ยของตัวอย่างเป็นแบบปกติ
- ใช้ไม่ได้กับการแจกแจงหางหนักที่ความแปรปรวนเป็นอนันต์
  (การแจกแจงแบบ Cauchy)
- ใช้ไม่ได้กับข้อมูลที่ไม่เป็นอิสระต่อกัน (อนุกรมเวลาที่ไม่ได้ปรับแก้)
```

### ข้อผิดพลาดทางสถิติที่พบบ่อยในเปเปอร์ ML

1. **ทดสอบบนชุดเทรน** รับประกัน overfitting กันข้อมูลที่โมเดลไม่เคยเห็นระหว่างเทรนไว้เสมอ

2. **ไม่มีช่วงความเชื่อมั่น** การรายงานความแม่นยำตัวเลขเดียวโดยไม่มีความไม่แน่นอน ทำให้ผลทำซ้ำไม่ได้และตรวจสอบไม่ได้

3. **มองข้ามการเปรียบเทียบหลายครั้ง** ทดสอบ 50 การตั้งค่าแล้วรายงานตัวที่ดีที่สุดโดยไม่ปรับแก้ ทำให้อัตราผลบวกลวงพองขึ้น

4. **สับสนนัยสำคัญทางสถิติกับในทางปฏิบัติ** p-value 0.001 สำหรับการปรับปรุงความแม่นยำ 0.01% ไม่มีความหมาย

5. **ใช้ความแม่นยำกับข้อมูลที่ไม่สมดุล** ความแม่นยำ 99% บนชุดข้อมูลที่ 99% เป็นคลาสลบแปลว่าโมเดลไม่ได้เรียนรู้อะไรเลย ให้ใช้ precision, recall, F1 หรือ AUC

6. **เลือกเฉพาะตัวชี้วัดที่ดี** รายงานแค่ตัวชี้วัดที่โมเดลของคุณชนะ การประเมินที่ซื่อสัตย์รายงานทุกตัวชี้วัดที่เกี่ยวข้อง

7. **สารสนเทศรั่วข้าม split ของเทรน/ทดสอบ** ทำ normalization ก่อนแบ่งข้อมูล หรือใช้ข้อมูลอนาคตทำนายอดีต

8. **ชุดทดสอบเล็กโดยไม่มีค่าประมาณความแปรปรวน** ประเมินบน 100 ตัวอย่างแล้วอ้างว่าดีขึ้น 2% นั่นคือสัญญาณรบกวน ไม่ใช่สัญญาณ

9. **สมมติว่าเป็นอิสระต่อกันทั้งที่ไม่ใช่** ภาพทางการแพทย์จากผู้ป่วยคนเดียวกัน ประโยคหลายประโยคจากเอกสารเดียวกัน การสังเกตภายในกลุ่มเดียวกันสัมพันธ์กัน

10. **P-hacking** ลองการทดสอบ ชุดย่อย หรือเกณฑ์การตัดออกต่าง ๆ จนได้ $p < 0.05$ ผลที่ได้เป็นผลพลอยได้จากการค้นหา

## ลงมือสร้าง (Building It)

คุณจะเขียน:

1. **สถิติเชิงพรรณนาตั้งแต่ศูนย์** (ค่าเฉลี่ย มัธยฐาน ฐานนิยม ส่วนเบี่ยงเบนมาตรฐาน เปอร์เซ็นไทล์ IQR)
2. **ฟังก์ชันสหสัมพันธ์** (เพียร์สันและสเปียร์แมน พร้อมเมทริกซ์ความแปรปรวนร่วม)
3. **การทดสอบสมมติฐาน** (one-sample t-test, two-sample t-test, chi-squared test)
4. **ช่วงความเชื่อมั่นแบบ bootstrap** (สำหรับสถิติใดก็ได้ ไม่ต้องสมมติอะไร)
5. **ตัวจำลอง A/B test** (สร้างข้อมูล ทดสอบ ตรวจหาความผิดพลาดแบบที่ 1 และแบบที่ 2)
6. **เดโมนัยสำคัญทางสถิติกับในทางปฏิบัติ** (แสดงว่า $n$ ที่ใหญ่ทำให้ทุกอย่าง "มีนัยสำคัญ")

ทั้งหมดเขียนตั้งแต่ศูนย์ด้วย `math` และ `random` เท่านั้น ไม่ใช้ numpy ไม่ใช้ scipy

## คำศัพท์สำคัญ

| คำศัพท์ | ความหมาย |
|---|---|
| Mean (ค่าเฉลี่ย) | ผลรวมของค่าหารด้วยจำนวน อ่อนไหวต่อค่าผิดปกติ |
| Median (มัธยฐาน) | ค่าตรงกลางของข้อมูลที่เรียงแล้ว ทนต่อค่าผิดปกติ |
| Standard deviation (ส่วนเบี่ยงเบนมาตรฐาน) | รากที่สองของความแปรปรวน วัดการกระจายในหน่วยเดิมของข้อมูล |
| Percentile (เปอร์เซ็นไทล์) | ค่าที่มีข้อมูลตามเปอร์เซ็นต์ที่กำหนดอยู่ต่ำกว่า |
| IQR | พิสัยระหว่างควอร์ไทล์ Q3 ลบ Q1 การกระจายของข้อมูล 50% ตรงกลาง |
| Pearson correlation (สหสัมพันธ์แบบเพียร์สัน) | วัดความสัมพันธ์เชิงเส้นระหว่างตัวแปรสองตัว ช่วง $[-1, 1]$ |
| Spearman correlation (สหสัมพันธ์แบบสเปียร์แมน) | วัดความสัมพันธ์แบบทางเดียวด้วยอันดับ |
| Covariance matrix (เมทริกซ์ความแปรปรวนร่วม) | เมทริกซ์ของความแปรปรวนร่วมระหว่างคุณลักษณะทุกคู่ |
| Null hypothesis (สมมติฐานว่าง) | ข้อสมมติตั้งต้นว่าไม่มีผลหรือไม่มีความต่าง |
| p-value | ความน่าจะเป็นของข้อมูลที่สุดโต่งขนาดนี้ เมื่อสมมติฐานว่างเป็นจริง |
| Confidence interval (ช่วงความเชื่อมั่น) | ช่วงของค่าที่เป็นไปได้ของพารามิเตอร์ที่ระดับความเชื่อมั่นหนึ่ง |
| t-test | ทดสอบว่าค่าเฉลี่ยต่างกันอย่างมีนัยสำคัญหรือไม่ ใช้การแจกแจง t |
| Chi-squared test | ทดสอบว่าความถี่ที่สังเกตได้ต่างจากความถี่ที่คาดหวังหรือไม่ |
| Effect size (ขนาดผล) | ขนาดของความต่างที่ไม่ขึ้นกับขนาดตัวอย่าง Cohen's d เป็นแบบที่พบบ่อย |
| Bonferroni correction | หารเกณฑ์นัยสำคัญด้วยจำนวนการทดสอบเพื่อควบคุมผลบวกลวง |
| Bootstrap | การสุ่มซ้ำแบบใส่คืนเพื่อประมาณการแจกแจงการสุ่มตัวอย่าง |
| Type I error (ความผิดพลาดแบบที่ 1) | ผลบวกลวง ปฏิเสธ H0 ทั้งที่มันเป็นจริง |
| Type II error (ความผิดพลาดแบบที่ 2) | ผลลบลวง ไม่ปฏิเสธ H0 ทั้งที่มันเป็นเท็จ |
| Statistical power (อำนาจทางสถิติ) | ความน่าจะเป็นที่จะปฏิเสธ H0 ที่เป็นเท็จได้ถูกต้อง Power = 1 ลบอัตราความผิดพลาดแบบที่ 2 |
| Central limit theorem (ทฤษฎีบทลิมิตสู่ส่วนกลาง) | ค่าเฉลี่ยของตัวอย่างลู่เข้าสู่การแจกแจงปกติเมื่อขนาดตัวอย่างโตขึ้น |
| Parametric test (การทดสอบแบบอิงพารามิเตอร์) | สมมติการแจกแจงแบบเฉพาะให้ข้อมูล (มักเป็นแบบปกติ) |
| Non-parametric test (การทดสอบแบบไม่อิงพารามิเตอร์) | ไม่สมมติเรื่องการแจกแจง ทำงานบนอันดับหรือเครื่องหมาย |
